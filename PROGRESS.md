# PROGRESS — Tadidy

Decisions taken along the way. Ticket progress lives in the tickets ([tickets/](tickets/README.md)); this file keeps what the tickets do not say: the choices made and why.

## Decisions and notes

Add here, with the date and the ticket (`TAD-xxx`), any decision taken along the way (technical choice, accepted deviation from the prototype or the spec, answer to a `blocked` ticket). One entry per decision, newest first, in English.

- 2026-10-29 · TAD-010 · The ticket asks for `insert_or_bump` and `enforce_limit` "in one transaction", but `insert_or_bump` already opens its own (`unchecked_transaction`) and SQLite refuses a nested `BEGIN`. The watcher runs the icon write, `insert_or_bump` and `enforce_limit` one after the other inside a single `with_conn` (the connection is held throughout, so nothing else writes in between), and emits the event after all three. A crash between the insert and the trim leaves the history one clip over its limit until the next capture trims it. Changing `insert_or_bump` to a savepoint belongs to a TAD-009 follow-up if it ever matters.
- 2026-10-29 · TAD-010 · `is_idle` (the 300 s rule) lives in `platform/idle.rs` next to `IdleProbe`, and `watcher::poll_interval` calls it: the coverage gate fails a changed file with no executable line ("in no report"), the same workaround as `SourceApp::new` in TAD-004, here with code that is really used.
- 2026-10-29 · TAD-010 · The `clip recorded` log line carries the clip id, kind, byte size and `elapsed_ms` since the tick saw the change, and no source app: the rule is "ids, kinds, sizes and durations only", so the source app and its icon are verified through the list UI (TAD-013), not through the logs.
- 2026-10-29 · TAD-010 · The watcher tests run one at a time (a static mutex held by `Harness`): `logs_never_contain_clip_text` installs a scoped `tracing` subscriber, and when another test thread reached the same `info!` callsite at that moment the subscriber missed its events (the test failed in about every run of the full suite and passed alone or with `--nocapture`). Five full-suite runs are green with the lock.
- 2026-10-29 · TAD-010 · `WatcherError` stores the storage error's code (`storage_error`, `storage_key_missing`…) as a string, not the `StorageError` itself: its text can carry SQLite's message, and the thread logs the code only. `Watcher::new` takes a `Services` struct (pasteboard, workspace, idle probe, event sink, clock) plus the database and the limit, instead of seven loose arguments.
- 2026-10-29 · TAD-010 · An own write whose plain text matches no clip emits nothing and still returns `OwnWrite`: a paste of something already deleted does not resurrect it. The own-write check reads the types before the frontmost app, so a paste is never attributed to an app.
- 2026-10-29 · TAD-008 · The runbook gained the step the ticket's *Risks* predicted: a self-signed `Tadidy Dev` certificate is listed as `CSSMERR_TP_NOT_TRUSTED` and `codesign` ignores it until its *Code Signing* trust is set to *Always Trust* (`security add-trusted-cert -p codeSign`). `find-identity -v` is the check; the `-v`-less list is noise (expired Apple certificates).
- 2026-10-29 · TAD-008 · `NSHumanReadableCopyright` reads `Copyright © 2026 Tadidy. All rights reserved.`: the ticket gives no holder name, so none of a real person is committed (acceptance criterion 7). The owner can change it later.
- 2026-10-29 · TAD-008 · Criterion 5 (Accessibility kept across rebuilds) is not checked in this ticket: the built app has no UI exposing `check_accessibility` yet, so QA step 7 stays for TAD-019. Criterion 6 (Keychain item read without prompt across rebuilds) was checked once TAD-007 was merged, on the real login keychain: QA step 8.
- 2026-10-29 · TAD-006 · Acceptance criterion 4 is narrowed (decided with the owner after review): a shortcut already held by another app is not detected. `global-hotkey` registers non-exclusively (`RegisterEventHotKey` options `0`) and macOS answers `noErr` to a second registration, checked with a two-process Carbon probe; only two exclusive registrations collide (`-9878`). `ShortcutError::Unavailable` stays for the refusals the system does return. TAD-017 should say in the preferences that the shortcut may be shared with another app.
- 2026-10-29 · TAD-006 · `AppState::shortcut_status()` is the read accessor of the shortcut's registration state: the preferences (TAD-017) show a registration failure through it, without reaching into the `Mutex`. `register_at_startup` writes the field directly; a later ticket that changes the shortcut will go through a setter.
- 2026-10-29 · TAD-006 · `onPanelShown(cb)` hands the callback the event's payload (`PanelShown`), not the Tauri event, and does not filter by window: the ticket's "filters on the payload" is read as "unwraps the payload". A listener that cares about one window compares `payload.window`.
- 2026-10-29 · TAD-006 · The Quick Panel is built with `PanelBuilder` (`tauri-nspanel` 2.1.1, from crates.io) rather than converting a window by hand: it applies the non-activating style mask, the level and the collection behaviour in the order the crate tests. The HUD material is applied after the build, on the same window. Hiding on click-away is the `windowDidResignKey` delegate callback, as the ticket asks, not Tauri's `Focused(false)` (the popover's mechanism). `hide_window` stays a plain `window.hide()` for the panel too; manual QA step 5 checks it.
- 2026-10-29 · TAD-006 · `windows::{Rect, Size, Position}` are small `f64` structs in physical pixels, so the placement (`center_in`, `target_screen`) is pure and tested without a monitor; `Position` is why the tray positioner's `Position` is now imported as `TrayPosition`. The placement is worked out in logical points end to end (`logical_rect`, `pointer_in_points`): tao reports the pointer in the primary monitor's scale, each monitor in its own scale and moves a window in the window's current scale, so mixing them put the panel on the wrong screen on a Retina laptop beside a 1× display (found in review).
- 2026-10-29 · TAD-006 · `windows/theme.ts` holds the system-theme follower that `popover.ts` had inline: `panel.ts` needs the same code, so it is shared instead of copied.
- 2026-10-29 · TAD-005 · The same coverage-gate trap as TAD-004 came back: `platform/keys.rs` and `platform/accessibility.rs` held only a trait, so the gate reported them "in no report". The owner chose the one-off workaround again, the gate staying as it is. - 2026-10-29 · TAD-005 · `AXIsProcessTrustedWithOptions` comes from `objc2-application-services` (the ticket allowed it) instead of a hand-written declaration; `objc2-core-foundation` is a direct dependency to build the `{ kAXTrustedCheckOptionPrompt: true }` dictionary. The keystroke uses `core-graphics` 0.25.0 as the ticket says, so two CoreFoundation bindings coexist in the macOS layer until the project picks one.
- 2026-10-29 · TAD-005 · `AppState` has no `Default` any more: it holds the platform services as `Arc<dyn …>` and `lib.rs` builds the real ones (`real_state`). Later tickets add their fields to `AppState::new`.
- 2026-10-29 · TAD-005 · `paste_probe` stays alive 500 ms after posting `⌘V`: run from a terminal, a process that exited right after `CGEvent::post` lost the event (reproduced twice, TextEdit stayed empty, `trusted: true` and `sent Command+V` printed); with the wait the text is pasted. The app is long-lived, so the key sender itself waits for nothing.
- 2026-10-29 · TAD-005 · The TCC grant goes to the program macOS holds responsible for the event: running `paste_probe` from a terminal, that is the terminal, not the probe binary. The manual QA says so.

- 2026-10-29 · TAD-009 · The ticket's criterion "12 clips of which 2 are pinned, `enforce_limit(Some(10))` deletes the 2 oldest unpinned" contradicts HIS-02 and the ticket's own *Scope* (pinned clips do not count toward the limit): with 10 unpinned clips nothing would go. The code and the test follow the spec: 12 unpinned clips plus 2 pinned (the oldest of all), the 2 oldest unpinned are deleted and both pinned ones stay.
- 2026-10-29 · TAD-009 · `clips_au` has a `WHEN` clause (an indexed column really changed) on top of `UPDATE OF plain_text, title, source_name`: SQLite fires `UPDATE OF` when a column is only *listed* in `SET`, and a bump from the same app lists `source_name`. Without the `WHEN`, every bump rewrote the index (9 changes instead of 1, seen by mutating the migration); a bump from a new app still re-indexes `source_name`. A bump never erases a known source app with an unknown one (`coalesce`).
- 2026-10-29 · TAD-009 · `PRAGMA incremental_vacuum` frees one page per `sqlite3_step`: `execute_batch` left 260 free pages after deleting a 1 MB clip, so `incremental_vacuum` steps the statement to its end.
- 2026-10-29 · TAD-009 · `OLDEST_UNPINNED_SQL` is `INDEXED BY idx_clips_last_copied`: left alone, the planner picked `idx_clips_recent` and a temporary B-tree for the `id` tie-break. `enforce_limit` first counts the unpinned clips (index-only) so the usual capture under the limit reads no row. The spec's data model now lists `idx_clips_last_copied` and the trigger rule.
- 2026-10-29 · TAD-009 · `ClipRecord` and `NewClip` print by hand (ids, kind, sizes): a derived `Debug` would put the clip's text in a failing test or a log, like `Representation`. `Cursor`, `ClipRecord::cursor()` and `ClipKind::{as_str, parse}` (plus `ToSql`/`FromSql`) are small additions to the ticket's list.
- 2026-10-29 · TAD-007 · The Keychain item is added with `SecItemAdd` and `kSecAttrAccessible = AfterFirstUnlockThisDeviceOnly` (a small `unsafe` block in `macos/keychain.rs`, `core-foundation` and `security-framework-sys` as direct dependencies): `security-framework`'s `PasswordOptions` has no accessibility attribute, and its `set_access_control` fails with `errSecMissingEntitlement` (-34018) because it needs the data-protection keychain. The file-based keychain accepts the attribute (status 0); whether it enforces it cannot be read back, but the item stays local either way.
- 2026-10-29 · TAD-007 · `StorageError` has an `Io` variant beyond the ticket's list: creating the data folder can fail. It maps to `storage_error` like `Sqlite` and `Migration`, with a fixed message (no path).
