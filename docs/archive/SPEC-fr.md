# Tadidy — Spécification

> **Tadidy** (« se souvenir » en malgache) est un gestionnaire d'historique du presse-papiers pour macOS qui vit dans la barre des menus, inspiré de [CopyClip](https://apps.apple.com/fr/app/copyclip-clipboard-history/id595191960?mt=12) et CopyClip 2.

| | |
|---|---|
| **Version du document** | 0.1 (brouillon) — 28/10/2026 |
| **Plateforme** | macOS 13 Ventura et suivants, Apple Silicon + Intel (binaire universel) |
| **Stack** | Rust (cœur) · Tauri 2 (shell) · Svelte 5 + TypeScript (UI) · SQLite chiffrée (SQLCipher) |
| **Langue de l'UI** | Anglais uniquement |
| **Distribution** | Usage perso, DMG direct (hors Mac App Store, donc sans sandbox) |
| **Synchronisation** | Aucune, stockage 100 % local |

---

## 1. Objectifs

### 1.1 Problème
macOS ne garde qu'**un seul** élément dans le presse-papiers. Copier écrase le précédent, et le texte, le lien ou l'image d'avant est perdu.

### 1.2 Objectifs
1. **Ne rien perdre** : tout ce qui est copié (texte, texte riche, images, fichiers, URLs) est historisé automatiquement.
2. **Retrouver vite** : ouvrir l'historique en un raccourci, taper quelques lettres, appuyer sur Entrée. Moins de 2 secondes du besoin au collage.
3. **Rester discret** : icône dans la barre des menus, pas d'icône dans le Dock, consommation CPU quasi nulle au repos.
4. **Rester privé** : base chiffrée, aucune donnée ne quitte la machine, expiration automatique des vieux clips.

### 1.3 Hors périmètre (v1)
- Synchronisation multi-Mac / iCloud
- Version Mac App Store (la sandbox empêche l'auto-collage)
- Localisation autre que l'anglais
- Windows / Linux (Tauri le permettrait, mais l'accès au presse-papiers et le collage sont spécifiques à macOS)

## 2. Glossaire

| Terme | Définition |
|---|---|
| **Clip** | Un élément de l'historique, correspondant à une copie. Il peut contenir plusieurs *représentations*. |
| **Représentation** | Un format de données d'un clip, identifié par son UTI (`public.utf8-plain-text`, `public.rtf`, `public.html`, `public.png`, `public.file-url`…). |
| **Épinglé (Pinned)** | Clip protégé de la purge et de la limite d'historique, affiché en haut ou dans un onglet dédié. |
| **Snippet** | Clip épinglé avec un **titre**, rangé dans une **collection**. Il peut être créé à la main, sans copie préalable. |
| **Popover** | Fenêtre qui s'ouvre sous l'icône de la barre des menus au clic. |
| **Quick Panel** | Panneau flottant ouvert par raccourci global, navigable au clavier, qui ne vole pas le focus de l'app active. |
| **Source app** | Application au premier plan au moment de la copie. |

### 4.2 Design
- Matériau translucide macOS (vibrancy `popover` / `hudWindow` via `window-vibrancy`), coins arrondis de 10 px.
- Police système (`-apple-system`, SF Pro), monospace (SF Mono) pour les clips détectés comme du code.
- Thème clair/sombre qui suit le système, avec surcharge possible.
- Animations ≤ 120 ms, désactivées si « Reduce motion » est actif.
- Accessibilité : labels ARIA, navigation clavier complète, contraste AA.

### 6.3 Surveillance du presse-papiers (watcher)

macOS ne fournit **aucune notification** de changement du presse-papiers. Il faut donc faire du polling sur `changeCount` :

1. Un thread dédié lit `NSPasteboard.generalPasteboard.changeCount` toutes les **300 ms** (réglage interne). C'est un simple entier, donc le coût est négligeable.
2. Si la valeur a changé :
   1. Lire `NSWorkspace.sharedWorkspace.frontmostApplication` pour récupérer le bundle ID et le nom de l'app source.
   2. Si l'app est exclue, ignorer le changement.
   3. Lire la liste des `types`. Si elle contient un type masqué ou transitoire, ignorer.
   4. Si elle contient le marqueur interne `app.tadidy.internal`, c'est une écriture de Tadidy : remonter le clip existant et s'arrêter (CAP-12).
   5. Extraire les représentations utiles dans cet ordre de priorité : `file-url` > image (`png`/`tiff`) > `rtf`/`html` > `url` > `utf8-plain-text`.
   6. Calculer le hash, dédupliquer, insérer en base, générer la miniature hors du thread de polling.
   7. Émettre l'événement Tauri `clips://changed` vers la webview.
3. Le polling est **adaptatif** : 300 ms par défaut, 1 s quand la session est inactive depuis plus de 5 min (`CGEventSourceSecondsSinceLastEventType`), pour économiser la batterie.

### 6.4 Collage (paster)

1. Écrire toutes les représentations du clip dans le presse-papiers, plus le type marqueur `app.tadidy.internal`.
2. Masquer le Quick Panel ou le popover. Comme le Quick Panel est un NSPanel non activant, l'app cible garde le focus. Le popover, lui, est une vraie fenêtre : il faut mémoriser l'app active à l'ouverture et la réactiver avec `NSRunningApplication.activateWithOptions`.
3. Attendre environ 50 ms, puis poster `CGEvent` keyDown/keyUp `V` avec le flag `Command` sur `kCGHIDEventTap`.
4. Si `AXIsProcessTrusted()` renvoie faux, on s'arrête à l'étape 1 (copier seulement) et on affiche SYS-03.
5. Option « Restore previous clipboard after paste » (P2) : remettre l'élément d'avant 500 ms plus tard.

### 6.7 Modèle de données (SQLite / SQLCipher)

```sql
CREATE TABLE clips (
  id              TEXT PRIMARY KEY,          -- UUID v7
  kind            TEXT NOT NULL,             -- 'text'|'rich'|'image'|'file'|'url'|'color'
  content_hash    TEXT NOT NULL UNIQUE,      -- SHA-256 de la représentation principale
  plain_text      TEXT,                      -- texte indexable (texte, alt d'image, noms de fichiers, URL)
  preview         TEXT,                      -- aperçu tronqué (300 car.)
  title           TEXT,                      -- snippets
  source_bundle   TEXT,
  source_name     TEXT,
  byte_size       INTEGER NOT NULL,
  width           INTEGER, height INTEGER,   -- images
  pinned          INTEGER NOT NULL DEFAULT 0,
  pin_order       REAL,
  collection_id   TEXT REFERENCES collections(id) ON DELETE SET NULL,
  copy_count      INTEGER NOT NULL DEFAULT 1,
  created_at      INTEGER NOT NULL,          -- ms epoch, première copie
  last_copied_at  INTEGER NOT NULL,          -- tri principal
  last_used_at    INTEGER                    -- dernier collage depuis Tadidy
);
CREATE INDEX idx_clips_recent ON clips(pinned, last_copied_at DESC);
CREATE INDEX idx_clips_kind   ON clips(kind, last_copied_at DESC);

CREATE TABLE representations (
  clip_id  TEXT NOT NULL REFERENCES clips(id) ON DELETE CASCADE,
  uti      TEXT NOT NULL,                    -- public.rtf, public.png, public.file-url…
  data     BLOB NOT NULL,
  PRIMARY KEY (clip_id, uti)
);

CREATE TABLE thumbnails (
  clip_id  TEXT PRIMARY KEY REFERENCES clips(id) ON DELETE CASCADE,
  png      BLOB NOT NULL
);

CREATE TABLE collections (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, sort REAL NOT NULL
);

CREATE TABLE excluded_apps (
  bundle_id TEXT PRIMARY KEY, name TEXT NOT NULL
);

CREATE TABLE settings (
  key TEXT PRIMARY KEY, value TEXT NOT NULL  -- JSON
);

CREATE TABLE app_icons (                      -- cache des icônes d'apps sources
  bundle_id TEXT PRIMARY KEY, png BLOB NOT NULL
);

CREATE VIRTUAL TABLE clips_fts USING fts5(
  plain_text, title, source_name,
  content='clips', content_rowid='rowid',
  tokenize='unicode61 remove_diacritics 2'
);
-- + triggers AFTER INSERT/UPDATE/DELETE sur clips pour synchroniser clips_fts
```

**Emplacement** : `~/Library/Application Support/app.tadidy/tadidy.db` (+ WAL).

**Choix « tout en base »** : les images sont stockées en BLOB dans la base chiffrée, plutôt qu'en fichiers. Cela donne un seul mécanisme de chiffrement, des suppressions atomiques et des sauvegardes simples. En contrepartie, la base grossit, d'où les limites CAP-13 et HIS-04, et un `VACUUM` incrémental (`auto_vacuum = INCREMENTAL`).

### 6.8 Chiffrement

- La base est chiffrée avec **SQLCipher** (AES-256, `PRAGMA key`).
- Au premier lancement, une clé aléatoire de 256 bits est générée et stockée dans le **Trousseau macOS** (`kSecClassGenericPassword`, service `app.tadidy`, accessibilité `AfterFirstUnlockThisDeviceOnly`).
- La clé ne quitte jamais la mémoire du processus et n'est jamais loguée.
- Si la clé est absente alors que la base existe (Trousseau réinitialisé), proposer de **réinitialiser l'historique**. Aucune récupération n'est possible.
- L'export JSON est **en clair** et le dialogue d'export le signale.
- ⚠️ Comme l'accès au Trousseau est lié à la signature du code, voir §8 (signature stable).

## 8. Permissions, signature, distribution

| Sujet | Décision |
|---|---|
| **Accessibilité (TCC)** | Requise pour l'auto-collage (`CGEvent`). Demandée à l'onboarding. Sans elle, l'app fonctionne en mode « copier seulement ». |
| **Sandbox** | Désactivée, puisqu'il n'y a pas d'App Store. Pas d'entitlement sandbox. |
| **`Info.plist`** | `LSUIElement = true` (pas d'icône Dock), `NSHumanReadableCopyright`, bundle ID `app.tadidy`. |
| **Signature** | ⚠️ **Important** : macOS associe la permission Accessibilité et l'accès au Trousseau à l'**identité de signature**. Une signature *ad hoc* change à chaque build : il faudrait alors réautoriser l'app à chaque fois. **Solution** : signer avec une identité stable, soit un certificat « Developer ID Application » (99 $/an, qui permet aussi la notarisation), soit, en usage strictement perso, un certificat auto-signé créé dans Trousseau d'accès et référencé dans `tauri.conf.json > bundle > macOS > signingIdentity`. |
| **Notarisation** | Optionnelle en usage perso. Indispensable si l'app est partagée, pour éviter le blocage Gatekeeper. |
| **Packaging** | `tauri build --target universal-apple-darwin` produit `.app` + `.dmg`. |
| **Mises à jour (P2)** | `tauri-plugin-updater` : clé de signature Tauri (différente de la signature Apple), `latest.json` publié sur GitHub Releases. |

## 9. Risques et points d'attention

| Risque | Impact | Mitigation |
|---|---|---|
| Le popover vole le focus, et `⌘V` part dans la mauvaise app | Élevé | Quick Panel en NSPanel non activant. Pour le popover, mémoriser l'app active et la réactiver avant le collage. À valider en spike (phase 0). |
| Permission Accessibilité perdue à chaque rebuild | Moyen (dev) | Signature stable dès le début (§8). En dev, lancer depuis le `.app` signé et non via `cargo run`. |
| Compilation SQLCipher (OpenSSL) en binaire universel | Moyen | Feature `bundled-sqlcipher-vendored-openssl`, testée en CI dès la phase 0. |
| Base qui grossit avec les images | Moyen | Limites de taille, quota, `incremental_vacuum` après les purges. |
| Polling et batterie | Faible | Polling adaptatif. Lire seulement `changeCount`, jamais le contenu, tant qu'il ne change pas. |
| Contenus exotiques (formats propriétaires d'apps comme Figma ou Office) | Faible | Ne garder que les UTI connus. Option P2 « keep all representations » avec une limite de taille. |
| Raccourci `⌘⇧V` déjà utilisé par une autre app | Faible | Détecter l'échec d'enregistrement et le signaler dans les préférences. |
| Empreinte mémoire WebKit | Faible | Fenêtres cachées, pas détruites. Une seule webview partagée popover/panel possible si nécessaire. |

## 10. Critères d'acceptation (MVP)

1. Copier un texte dans n'importe quelle app : il apparaît en tête du popover en moins de 500 ms.
2. Copier deux fois le même texte : un seul clip, remonté en tête, `copy_count = 2`.
3. `⌘⇧V` dans TextEdit, `↓`, `Entrée` : le 2ᵉ clip est collé dans TextEdit, qui garde le focus.
4. Permission Accessibilité retirée : `Entrée` copie seulement et la bannière s'affiche.
5. Avec la limite à 10, une 11ᵉ copie supprime la plus ancienne non épinglée.
6. Taper « sel » filtre en moins de 50 ms et n'affiche que les clips contenant « sel ».
7. Après redémarrage du Mac, Tadidy est lancé (si l'option est cochée) et l'historique est intact.
8. Ouvrir `tadidy.db` avec `sqlite3` sans la clé échoue (« file is not a database »).
9. Aucune icône dans le Dock ni dans `⌘Tab`.
10. CPU au repos < 0,5 % mesuré sur 10 min dans le Moniteur d'activité.
