# AGENTS.md — Tadidy

The working contract for every agent (Claude Code through `CLAUDE.md`, Codex, Cursor…) and every human working on Tadidy. It says **what to build**, **where**, **how**, and **how to keep the tracking up to date**. If a ticket contradicts this file, this file wins; report the gap with `ticket-problem`.

## 1. The product in one minute

Tadidy ("remember" in Malagasy) is a macOS clipboard-history manager that lives in the menu bar. It records everything you copy (plain text, rich text, images, files, links) in an encrypted local database, finds it again in a few keystrokes, and pastes it back into the app you were using. Inspired by CopyClip and CopyClip 2.

Sources of truth, in this order:

1. **[docs/spec/](docs/spec/README.md)**: the specification, one part per file, with stable anchors that tickets cite.
2. **[docs/prototype/prototype.html](docs/prototype/prototype.html)**: every screen, UI text, element id and state the front must reproduce. The visual system (tokens, components, rules) is in **[DESIGN.md](DESIGN.md)**.
3. **The tickets** `TAD-xxx` in **[tickets/](tickets/README.md)** (how they work: [docs/guides/tickets.md](docs/guides/tickets.md)).

Architecture decisions live in [docs/adr/](docs/adr/README.md). Versions, paths and tools are listed in [docs/reference.md](docs/reference.md). The French first draft of the spec is in [docs/archive/](docs/archive/) and is no longer authoritative.

## 2. Non-negotiable rules

- **Nothing leaves the machine.** No network call except the optional update check (P2). No telemetry, no analytics, no crash reporter that uploads anything.
- **Clip content is never logged**: no `println!`, `dbg!`, `tracing` field, panic message, test snapshot or screenshot that contains clip content. Log ids, kinds, sizes and durations only.
- **The database is always encrypted** (SQLCipher). The key lives only in the macOS Keychain and in process memory; it is never written to disk, logged, or passed to the webview.
- **The webview is untrusted.** All clipboard, database, Keychain and Accessibility access happens in Rust. The front only calls typed IPC commands; Tauri capabilities grant the minimum.
- **The agent never merges** a pull request and never pushes to `main`. The human reviews and merges.
- **Hooks are never bypassed**: no `--no-verify`, no `LEFTHOOK=0`. There is no CI: the hooks are the only gate ([ADR 0004](docs/adr/0004-local-hooks-no-ci.md)).
- **Always the latest stable version** of every dependency.
  - npm: before any `pnpm add`, run `pnpm view <pkg> version` (npm tag `latest`) and install that exact number. Forbidden: dist-tags and versions marked `canary`, `alpha`, `beta`, `rc`, `next`, `experimental`, `nightly`.
  - Rust: `cargo add <crate>` (it picks the latest stable release); check with `cargo info <crate>` if in doubt. Never a pre-release (`-alpha`, `-beta`, `-rc`).
  - Never copy a version number from a ticket, from [docs/reference.md](docs/reference.md) or from memory when the registry has a newer stable one. Stay within the **expected major** (§6); a major jump needs an ADR. After installing, update [docs/reference.md](docs/reference.md).
  - Tauri: the `tauri` crate, `@tauri-apps/api`, `@tauri-apps/cli` and every `tauri-plugin-*` / `@tauri-apps/plugin-*` pair stay on the same major and minor.

## 3. Settled questions (valid everywhere)

| Topic | Rule |
|---|---|
| Clip kinds | `text`, `rich`, `image`, `file`, `url`, `color` (the `kind` column and the `ClipKind` type) |
| Paste modes | `default`, `plain`; result `pasted` or `copied_only` (no Accessibility permission) |
| Own writes | Every write to the pasteboard by Tadidy carries the marker type `app.tadidy.internal`; the watcher never records it as a new clip |
| Ignored types | `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType` |
| Ids | UUID v7 strings |
| Timestamps | Milliseconds since the Unix epoch, `i64` in Rust, `number` in TypeScript |
| Events | `clips://changed`, `settings://changed`, `accessibility://changed`, `panel://shown`, `menu://clear-history` |
| Bundle id / data dir | `app.tadidy`, `~/Library/Application Support/app.tadidy/` |

## 4. Repository layout

A standard Tauri 2 app at the root (no monorepo tool): the Svelte front in `src/`, the Rust core in `src-tauri/`. Both are created by TAD-001.

```
tadidy/
├── AGENTS.md, CLAUDE.md         ← this contract (CLAUDE.md only contains @AGENTS.md)
├── DESIGN.md, GLOSSARY.md       ← visual system; domain vocabulary
├── PROGRESS.md                  ← decisions taken along the way
├── lefthook.yml                 ← local git hooks (the only gate, no CI)
├── tickets/                     ← TAD-xxx.md, one file per ticket
├── src/                         ← Svelte 5 + TypeScript front (TAD-001)
├── src-tauri/                   ← Rust core, Tauri shell (TAD-001)
├── docs/
│   ├── spec/                    ← the specification (source of truth) + spec.html
│   ├── prototype/               ← clickable reference prototype
│   ├── adr/                     ← numbered architecture decisions
│   ├── reference.md             ← versions, tools, paths
│   ├── guides/                  ← tickets, manual QA
│   └── plans/ solutions/ runbooks/ archive/
├── scripts/                     ← repo scripts (node:test), check.sh, spec build
├── .claude/skills/              ← project skills
└── .github/                     ← pull request template (no workflow)
```

- **IPC contract**: Rust types exposed to the front derive `ts_rs::TS` and are exported to `src/lib/bindings/` ([ADR 0006](docs/adr/0006-ts-bindings-with-ts-rs.md)). Never hand-write a TypeScript type that exists in Rust. A change to an IPC type and its front usage go in **the same pull request**.

## 6. Stack

- **Core**: Rust (stable toolchain, `rust-toolchain.toml`), Tauri 2 (`tray-icon`, `macos-private-api`), `objc2` + `objc2-app-kit` + `objc2-foundation`, `core-graphics`, `rusqlite` with `bundled-sqlcipher-vendored-openssl` + `rusqlite_migration`, `security-framework`, `sha2`, `image`, `uuid` (v7), `serde`, `thiserror`, `anyhow`, `tracing`, `ts-rs`. Plugins: `global-shortcut`, `autostart`, `positioner`; `tauri-nspanel`, `window-vibrancy`.
- **Front**: Svelte 5 (runes), TypeScript strict, Vite, `@tauri-apps/api`. Tests: Vitest + `@testing-library/svelte` + jsdom, Playwright (Chromium, against the Vite dev server with mocked IPC).
- **Tools**: Node 24 LTS (`.nvmrc`), pnpm 10, lefthook, gitleaks, cargo-llvm-cov.
- **Expected majors** (a change needs an ADR): Tauri 2, Svelte 5; the other majors (Vite, TypeScript, Vitest, ESLint, rusqlite…) are fixed by TAD-001 at the newest stable major that the rest of the toolchain accepts (peer dependencies: e.g. TypeScript must be supported by `svelte-check` and `typescript-eslint`), and recorded in [docs/reference.md](docs/reference.md). That file is a **snapshot** of what is installed, not a list to copy.
- **Tauri 3 is a pre-release** on crates.io and npm: install the Tauri 2 line explicitly (`cargo add tauri@2`, `pnpm add @tauri-apps/api@<latest 2.x>`).

## 7. Tracking: tickets in markdown

Tracking lives in **`tickets/TAD-xxx.md`**, one file per ticket, with a YAML header (`status`, `phase`, `priority`, `blockedBy`, `branch`, `pr`…) and a markdown body ([ADR 0003](docs/adr/0003-tickets-as-markdown.md)). Full rules: **[docs/guides/tickets.md](docs/guides/tickets.md)**. The header is only changed with `node scripts/tickets.mjs set`, through the `ticket-*` skills.

| Status | Meaning |
|---|---|
| `todo` | To do. **Ready** when every ticket in `blockedBy` is `done`. |
| `in-progress` | Claimed; its branch exists. One session works on one ticket. |
| `review` | Pull request open, waiting for the human's review. |
| `done` | The human approved the pull request; closing note written. The merge comes after, by the human. |
| `blocked` | Needs a human decision: cause, attempts and the expected decision are in the ticket's *Notes*. |
| `canceled` | Abandoned or duplicate; the reason is in *Notes*. |

The status travels **with the ticket's branch**: `node scripts/tickets.mjs` reads the ticket file on `main` and on the local `tad-xxx-*` branch, and the branch wins.

## 8. Work loop

1. The human says **"What should I do today?"** (or "let's continue"). **`tadidy-session`** answers with one ticket: an in-progress or in-review ticket first, otherwise the next ready one. An in-progress ticket whose branch is checked out (main folder or worktree) belongs to another session: it is never proposed. It asks **"Shall I do it?"**. The human can also name a ticket ("take TAD-009"). No command to type.
2. **Yes** → **`ticket-claim`**, then **`ticket-implement`** (plan, **`tdd`**, verify, **`self-review`**, **`prototype-parity`** for UI tickets).
3. At the end, the agent opens the pull request to `main` (**`ticket-update`**, opening) without asking; the ticket goes to `review`. Optionally, the human asks another session for an agent review (**`review-pr`**: comments posted on the pull request, never an approval). The human reviews on GitHub, then says **"address the review"** → **`address-pr`**, as many rounds as needed.
4. The human approves ("approved", "LGTM", or a GitHub approval) → **`ticket-update`** (closing: closing note, `done`, pushed on the branch), then the human merges, then **"Shall I take the next one?"**.
5. Stuck? **`ticket-problem`**, then ask again.
6. Missing work? **`ticket-create`**, not in the current ticket.

Stay in scope: what is under *Out of scope* is not done in this ticket, even if it is quick. One session = one ticket: start the next one from a clean context.

**Parallel sessions never share a folder.** When the main folder is busy (not on `main`, or uncommitted changes: `node scripts/worktree.mjs status`), a session working on another ticket or reviewing a pull request works in its own git worktree in `../tadidy-worktrees/`, and never switches branch, stashes or commits in the main folder. Rules and traps: [docs/guides/parallel-sessions.md](docs/guides/parallel-sessions.md).

## 9. TDD: mandatory for every ticket

- Every ticket has a non-empty *Tests* section: these are the tests to write **before** the code.
- **Red**: write the test for one acceptance criterion, run it, watch it fail for the right reason. Commit `test(TAD-042): <criterion>`.
- **Green**: the minimum code to make it pass. Commit `feat(TAD-042): <criterion>`.
- **Refactor**: clean up, tests still green. Commit `refactor(TAD-042): …` if useful.
- No production code without a red test that asks for it. A bug fix starts with a test that reproduces it (`fix(TAD-042): …`).
- Coverage ≥ 80 % of lines on changed files, Rust (`cargo llvm-cov`) and front (`pnpm test:cov`). Never lower a threshold to pass.
- **The macOS layer exception**: code that only calls AppKit, CoreGraphics, the Keychain or Accessibility (`src-tauri/src/macos/`) cannot run in a unit test. Keep it **thin**, behind a trait (`Pasteboard`, `Workspace`, `KeySender`, `KeyStore`…) so the logic around it is tested with fakes. That folder is excluded from the coverage gate; each behaviour it adds gets a step in [docs/guides/manual-qa.md](docs/guides/manual-qa.md) and the ticket's *Tests → Manual* section, run and reported in the pull request.

## 10. Definition of done

A ticket is `done` only if **all** of the following are true:

1. The tests were written before the code (`test(…)` commit before `feat(…)`) and were seen failing.
2. Every step is checked in the ticket and every acceptance criterion is verified by a test (or by a manual QA step for the macOS layer, §9).
3. Every command of the *Verification* section passes; `scripts/check.sh` passes; coverage ≥ 80 % on changed files.
4. No secret, clip content or personal data added (code, logs, fixtures, screenshots).
5. UI ticket: the view matches the prototype (texts, ids, states) — `prototype-parity` — and the [DESIGN.md](DESIGN.md) UI checklist is filled in the pull request.
6. The listed files exist; every gap is explained in the closing note.
7. The pull request to `main` is open, **the human approved it**, the closing note is in the ticket's *Notes*, and the ticket is `done` (skill `ticket-update`).
8. Every decision taken during the ticket is recorded in *Decisions and notes* of `PROGRESS.md`.

Never announce "done" without running the commands and reading their output (skill `verification-before-completion`).

## 11. Branches and pull requests

One long-lived branch: **`main`** ([ADR 0002](docs/adr/0002-main-and-a-pull-request-per-ticket.md)). Releases are tags `vX.Y.Z` on `main` (skill `release-dmg`).

- **One branch and one pull request per ticket**: branch `tad-042-<short-slug>` created from an up-to-date `main`, pull request to `main`.
- Title `TAD-042 — <ticket title>`; description from [.github/pull_request_template.md](.github/pull_request_template.md): link to the ticket file, acceptance criteria checked, verification commands actually run with their result, manual QA results, deviations.
- Pull request < 500 changed lines when possible; otherwise split the ticket (`ticket-create`).
- **Review by the human.** The agent addresses comments with `address-pr`: check each one before applying it, answer each one in its thread.
- **Merge**: by the human only, with a **merge commit or rebase**, never squash: the `test(…)` → `feat(…)` order must stay visible in `main`'s history.
- No force push on `main`. Force push on a ticket branch only if the human asks.

## 13. Rust conventions (`src-tauri/`)

- `cargo fmt`, `cargo clippy --all-targets -- -D warnings` clean. `unsafe` only in `src/macos/`, each block with a `// SAFETY:` comment.
- **Errors**: a `thiserror` enum per module; IPC commands return `Result<T, AppError>` where `AppError` serializes to `{ code, message }` (never clip content, never a path under the user's home in clear). No `unwrap()` / `expect()` outside tests and `main` setup.
- **Layers**: `commands.rs` (thin IPC, no logic) → services (`watcher`, `paster`, `purger`, `storage::*`) → `macos/` (thin FFI behind traits). Services depend on traits, not on `macos/` directly, so tests inject fakes. `main.rs` and `lib.rs` only wire Tauri (plugins, state, command registration): no logic there, since the coverage gate does not look at them.
- **Threads**: the watcher runs on its own thread; AppKit calls that need the main thread go through `app.run_on_main_thread`. Never block the main thread on SQLite.
- **SQL**: parameters only (`params![]`), never string formatting. Migrations are append-only (skill `db-migration`).
- **Tests**: unit tests in a `#[cfg(test)] mod tests` next to the code; integration tests in `src-tauri/tests/`. Temporary databases in `tempfile` dirs; a fixed test key, never the Keychain.
- **macOS layer**: `src-tauri/src/macos/` is the only place that imports `objc2*`, `core-graphics`, `security-framework` or Accessibility FFI.

## 14. Front conventions (`src/`)

- Svelte 5 runes (`$state`, `$derived`, `$effect`, `$props`); no legacy stores for new code. TypeScript strict (`strict`, `noUncheckedIndexedAccess`); no `any`, no `@ts-ignore` without a comment explaining the constraint.
- All IPC goes through `src/lib/api.ts` (typed wrappers over `invoke` / `listen`) using the generated types of `src/lib/bindings/`. Components never call `invoke` directly.
- **UI texts are verbatim from the prototype** (English). Element ids from the prototype are kept as `id` attributes so tests and `prototype-parity` can find them.
- Styles use the DESIGN.md tokens (CSS custom properties); no hard-coded colors, sizes or durations.
- Keyboard handling is centralized in `src/lib/keyboard.ts`; every action is reachable without a mouse.
- **Tests**: `*.test.ts` next to the code (Vitest + Testing Library, IPC mocked with `@tauri-apps/api/mocks`); end-to-end flows in `e2e/*.spec.ts` (Playwright against the Vite dev server, IPC mocked).

## 15. Common conventions

- **Everything in English**: code, comments, UI, docs, tickets, commits, pull requests, `PROGRESS.md` ([ADR 0005](docs/adr/0005-english-everywhere.md)). The human may speak French in the conversation; the agent answers in the human's language but writes the repository in English.
- **Naming**: Rust `snake_case` files and modules; TypeScript files `kebab-case.ts`, Svelte components `PascalCase.svelte`.
- **Commits**: Conventional Commits with the ticket id: `test(TAD-042): …`, `feat(TAD-042): …`, `fix(TAD-042): …`, `refactor(TAD-042): …`, `docs(TAD-042): …`, `chore(TAD-042): …`, `build(TAD-042): …`, `perf(TAD-042): …`, `wip(TAD-042): …`. Subject ≤ 72 characters, imperative, e.g. `test(TAD-010): ignore clips written by Tadidy`. The `commit-msg` hook enforces it.
- **Dependencies**: §2. A dependency not listed in the ticket is noted in the closing note.

## 17. Never

- Change a ticket's header by hand or without the `ticket-*` skills; delete a ticket file (cancel it instead).
- Mark a ticket `done` without tests, without commits, without the human's approval, or with a `blockedBy` ticket that is not `done`.
- Write production code before the red test.
- Go beyond the ticket's scope, or "improve" the prototype on your own initiative: a gap is discussed (`ticket-problem`) or becomes a ticket (`ticket-create`).
- Commit a secret, a `.env`, a signing certificate, a database file, or a screenshot showing real clipboard content.
- Log, print or persist clip content outside the encrypted database.
- Merge a pull request, push to `main`, force-push `main`, or bypass a hook.
- Call `invoke` from a component, or hand-write a type that `ts-rs` generates.
- Install a dependency at a pinned or pre-release version when a newer stable exists (§2).
- Relax a rule of section 2 "to go faster".
