# TAD-027 — Offer the history reset for a malformed key and a database that cannot be migrated

> Phase 1 · P1 · core · Discovered in: TAD-022 (review of the pull request)

## Context

TAD-022 offers the history reset only for `storage_key_missing` and `storage_wrong_key`; every other open failure may be temporary (a locked or denied Keychain), and a reset would then throw away a history that is only out of reach. Two failures are permanent but map to the generic `storage_error`: a Keychain key of the wrong length (`KeyStoreError::Malformed`) and a database that cannot be migrated (damaged file, or a schema newer than the app). Today the user sees "nothing is being recorded" with no way out.

## Scope

- Give each of the two causes its own `AppError` code, distinct from the temporary `storage_error`.
- Mark them resettable in `StorageStatus` (`canReset`), so the unavailable state shows **Reset history…** for them.
- Decide, for a schema newer than the app, whether the reset is the right offer (the old file is kept as `.bak`, but an app update would open it): record the decision in `PROGRESS.md`.

## Out of scope

- A retry button or an automatic retry for the temporary failures.
- Opening the `.bak` file again (no recovery flow).

## Steps

- [x] Red tests: `AppError::from(StorageError)` for the two causes, `StorageStatus::unavailable` for their codes, `reset_history` accepting them.
- [x] Add the codes and make them resettable.
