# TAD-021 — Skip tickets taken by another session when proposing the next one

> Phase 0 · P1 · repo · Discovered in: TAD-002 (a new session proposed TAD-002, which another session was implementing in the main folder, and TAD-020 as in review although it was done on `main`)

## Context

`tadidy-session` proposes an `in-progress` ticket first, even when its branch is checked out in the main folder or a worktree: another session is working on it, so the new session must propose the next ready ticket instead. It also trusts a stale local `tad-xxx` branch over `main`: a ticket closed on `main` (`done`) still shows as `review` while its old branch exists.

## Scope

- `scripts/tickets.mjs`: each ticket carries `checkedOut`, the folder where its branch is checked out (main folder or worktree), or `null`. `next` separates `taken` (`in-progress` and checked out somewhere: another session owns it) from `active` (the ones this session may resume or follow up).
- `scripts/tickets.mjs`: a ticket that is `done` or `canceled` on `main` (`origin/main`, or `main` without a remote) keeps that status even when a local `tad-xxx` branch says otherwise.
- The rule in the skill `tadidy-session`, `docs/guides/tickets.md` (order of proposal), `docs/guides/parallel-sessions.md` and AGENTS.md §8.

## Out of scope

- Detecting whether the session that holds a checked-out branch is still alive: the human says so by naming the ticket.
- Deleting stale local branches.

## Acceptance criteria

- [x] Given an `in-progress` ticket whose branch is checked out in a worktree or the main folder, when `node scripts/tickets.mjs next` runs, then the ticket is listed under `taken`, not `active`, and the next ready ticket is proposed.
- [x] Given an `in-progress` ticket whose branch is checked out nowhere, when `next` runs, then it stays in `active` (to resume).
- [x] Given a ticket `done` on `main` and `review` on a stale local branch, when the tickets are loaded, then its status is `done` and its source is `main`.
