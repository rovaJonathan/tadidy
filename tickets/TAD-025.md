# TAD-025 — Make Launch at login work on the signed build

> Phase 1 · P0 · full · Discovered in: TAD-019 (MVP criterion 7 cannot be run: the option cannot be switched on)

## Context

On the signed universal build installed in `/Applications` (identity `Tadidy Dev`, fresh database), the owner cannot switch *Launch at login* on in Preferences › General. Tadidy never appears in *System Settings → General → Login Items & Extensions* (neither under "Open at Login" nor under "Allow in the Background"). Without it MVP criterion 7 ("after restarting the Mac, Tadidy is running") cannot be met or even tested.

What was observed, with `RUST_LOG=tadidy_lib=debug` and stderr redirected to a file:

- no `the login item could not be changed` warning: `SmLoginItem::set_enabled` did not return an error, or it was not reached;
- `sfltool dumpbtm` holds no record of Tadidy, and the unified log has no `ServiceManagement` line for the process.

So either the IPC patch never reaches `Effects::apply` (the checkbox reverts on a failure that is not shown), or `AppService::register()` returns `Ok` without registering. Which one is the first thing to find out.

## Scope

- Reproduce on the installed signed build and find where the chain stops: the front (`GeneralTab.svelte` › `setLaunchAtLogin` › `store.patch`), the command (`update_settings`), `settings::Effects::apply`, then `macos/login_item.rs`.
- Fix the cause. If `SMAppService` needs more than the current signature (an approval step, a different identity, the app being in `/Applications`), say so in the UI and in `docs/runbooks/signing-identity.md`.
- When the system leaves the item in `RequiresApproval`, tell the user in Preferences how to approve it, instead of unchecking silently.
- Add the missing manual QA step to `docs/guides/manual-qa.md` under `### TAD-025`.

## Out of scope

- Notarization and Developer ID signing (skill `release-dmg`).
- Changing the stored setting model or its default (`false`).

## Acceptance criteria

- [ ] Given the signed build in `/Applications`, when *Launch at login* is switched on, then Tadidy is listed and enabled in *System Settings → General → Login Items & Extensions*.
- [ ] Given the system leaves the item waiting for approval, when Preferences shows the option, then the box is not silently unchecked and a message says how to approve it.
- [ ] Given a failure to change the login item, then the box shows the system's state and an error text is visible under the label.
- [ ] Given *Launch at login* on and a restart of the Mac, then Tadidy is running with its tray icon and no window open (MVP criterion 7).
