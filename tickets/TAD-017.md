# TAD-017 — Preferences window: General and Shortcuts

> Phase 1 · P0 · full

## Context

The MVP needs the General and Shortcuts tabs: launch at login (SYS-01), history size (HIS-02), confirm before delete (HIS-05) and the Quick Panel shortcut (QPN-01), with a visible error when the shortcut is taken. The window must take focus although Tadidy is an `Accessory` app. It also provides `open_preferences`, used by the browser (TAD-016) and the tray (TAD-018).

## Scope

- Window label `settings`, `settings.html` → `src/windows/settings.ts` → `src/windows/Settings.svelte`, ≈ 640 × 480, standard window, created on demand by `windows::open_preferences(app)` (existing → shown and focused).
- Activation policy `Regular` while the window exists, back to `Accessory` when it closes (spec *Windows*); the decision kept in a small pure `PolicySwitch` tested in Rust.
- IPC `open_preferences() -> ()` and `get_shortcut_status() -> ShortcutStatus` (TAD-006 type); wrappers `openPreferences()`, `getShortcutStatus()`.
- `src-tauri/src/login_item.rs`: `trait LoginItem { fn is_enabled(&self) -> Result<bool, _>; fn set_enabled(&self, on: bool) -> Result<(), _>; }`, implemented with `tauri-plugin-autostart`, `FakeLoginItem` for tests. At startup the stored `launchAtLogin` is reconciled with the system state (the system wins: a user who removed Tadidy from Login Items is respected).
- `set_settings` (TAD-011) gains side effects, before persisting:
  - `launchAtLogin` changed → `LoginItem::set_enabled`; failure → `AppError { code: "login_item_failed" }`, setting unchanged;
  - `quickPanelShortcut` changed → register the new accelerator first; failure → `AppError { code: "shortcut_unavailable" | "invalid_settings" }`, old shortcut kept; success → old one unregistered; `ShortcutStatus` updated. At startup the stored shortcut (not the constant) is registered.
- Front: sidebar with only `#prefs-general` and `#prefs-shortcuts` (the other tabs of the prototype are **not rendered**: phase 2).
  - `GeneralTab.svelte`: launch at login, history size (presets and "Unlimited" as in the prototype; `0` = unlimited), confirm before delete;
  - `ShortcutsTab.svelte` + `ShortcutRecorder.svelte`: records a key combination, shows it as symbols (`⌘⇧V`), saves through `setSettings`, shows the conflict error from `set_settings` or from `getShortcutStatus()` at open;
  - `src/lib/shortcut.ts`: `toAccelerator(KeyboardEvent) -> string | null` (needs `⌘`, `⌃` or `⌥`; rejects modifier-only), `formatAccelerator(string) -> string`;
  - `src/lib/stores/settings.svelte.ts`: `SettingsStore` (load, patch, follows `settings://changed`), reused by TAD-016.
- Texts and controls verbatim from the prototype.

## Out of scope

- P1 settings of these tabs (auto-expire, show pinned on top, sound on copy, quick paste ⌘1–9, plain text by default) and the Capture, Appearance, Storage & Privacy and About tabs (phase 2).
- Wiring the tray's Preferences… item (TAD-018).

## Acceptance criteria

- [ ] Given `open_preferences` twice, then one `settings` window exists, focused, and Tadidy shows in the Dock and `⌘Tab` while it is open; after closing it, Tadidy is `Accessory` again.
- [ ] Given the General tab, when "Launch at login" is checked, then `set_settings({ launchAtLogin: true })` is invoked and the login item is enabled; a failure shows the error and unchecks the box.
- [ ] Given the history size set to 10, then `set_settings({ historySize: 10 })` is invoked; "Unlimited" sends `0`.
- [ ] Given the recorder focused, when `⌃⌥V` is pressed, then it shows `⌃⌥V` and saves `Ctrl+Alt+V`; pressing `V` alone or `⇧` alone is refused.
- [ ] Given a shortcut already taken by another app, when it is saved, then the tab shows the prototype's conflict error and the previous shortcut still opens the Quick Panel.
- [ ] Given the default shortcut failed at startup, when the Shortcuts tab opens, then the conflict error is shown.
- [ ] Given Tadidy removed from Login Items in System Settings, when Tadidy starts, then `launchAtLogin` reads `false`.
- [ ] Given the window, then only `#prefs-general` and `#prefs-shortcuts` exist in the DOM.

## Risks

- The autostart plugin's macOS launcher may not use `SMAppService` (SYS-01) → check its options; if it only offers a LaunchAgent or AppleScript, choose between it and `smappservice-rs` in an ADR.
- An `Accessory` app's window does not come to the front → switch to `Regular` before showing, then focus.
- Re-registering a shortcut that fails leaves none → register the new one first, unregister the old one only on success.
