# TAD-003 — Tray icon, tray menu and hidden popover window

> Phase 0 · P0 · full

## Context

Phase 0 spike "Tauri tray + popover": prove that a menu-bar-only app can show a pre-created popover under its icon in under 100 ms and hide it cleanly. The popover window is the host of the clip browser (TAD-016); the tray menu is completed by TAD-018.

## Scope

- Template tray icon (MNU-01): `src-tauri/icons/tray/tray-template.png` (@1x) and `tray-template@2x.png`, black + alpha, `icon_as_template(true)`, so it follows light/dark mode.
- `src-tauri/src/tray.rs`: `TrayIconBuilder` with `show_menu_on_left_click(false)`; left click (button up) toggles the popover (MNU-02); right click opens the native menu (MNU-03).
- Menu model as a pure function `tray::menu_items() -> Vec<TrayItem>` (`id`, `label`, `enabled`, separators), labels and keyboard equivalents (`⌘,` on Preferences…, `⌘Q` on Quit Tadidy) verbatim from the prototype `#tray-menu`. Item ids: `preferences`, `clear-history`, `about`, `check-updates`, `quit`.
  - `quit` is wired here (`app.exit(0)`).
  - `preferences`, `clear-history` and `about` are present but **disabled**; TAD-018 enables and wires them.
  - `check-updates` stays disabled until the P2 updater ticket (SYS-04).
- `src-tauri/src/windows.rs`: the popover window, label `popover`, `popover.html`, ≈ 380 × 520, undecorated, transparent, `alwaysOnTop`, `skipTaskbar`, created hidden in `setup`; `toggle_popover(app)` positions it with `tauri-plugin-positioner` (`Position::TrayBottomCenter`, events forwarded with `on_tray_event`), shows and focuses it; hidden on `WindowEvent::Focused(false)` (MNU-04); vibrancy `Popover` material with 10 px corners (`window-vibrancy`).
- Toggle debounce: `PopoverToggle` (pure, injectable clock) ignores a tray click that arrives < 250 ms after a focus-loss hide, so clicking the icon while the popover is open closes it instead of reopening it.
- IPC `hide_window()`: hides the calling window (label read from the `WebviewWindow` argument); wrapper `hideWindow()`.
- Front: `popover.html` → `src/windows/popover.ts` → `src/windows/Popover.svelte` (placeholder content until TAD-016), `Esc` calls `hideWindow()` (MNU-04); `src/styles/tokens.css` with the DESIGN.md tokens, imported by every window entry; second Vite entry in `vite.config.ts`.
- Capability `default.json` lists the `popover` window.
- Activation policy stays `Accessory` (MNU-06) with the window shown.

## Out of scope

- The clip browser inside the popover (TAD-013, TAD-016); the footer and the Accessibility banner.
- Wiring Preferences…, Clear history…, About (TAD-018); Check for updates… (P2).
- The Quick Panel (TAD-006).

## Acceptance criteria

- [ ] Given the menu model, when it is built, then its labels and order match the prototype `#tray-menu` and only `quit` is enabled.
- [ ] Given the popover was hidden by a focus loss less than 250 ms ago, when the tray icon is clicked, then the popover stays hidden.
- [ ] Given the popover is hidden, when the tray icon is left-clicked, then the popover appears under the icon with its content focused.
- [ ] Given the popover is visible, when it loses focus or `Esc` is pressed, then it hides (the window is hidden, not destroyed).
- [ ] Given the tray menu, when Quit Tadidy is chosen, then the process exits.
- [ ] Given the popover is visible, then Tadidy has no Dock icon and is absent from `⌘Tab`.
