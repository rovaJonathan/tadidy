# TAD-008 — Stable signing identity and universal build

> Phase 0 · P0 · repo

## Context

macOS ties the Accessibility permission and the Keychain item to the code signature. With ad-hoc signing, every rebuild silently breaks auto-paste and the database key. This ticket makes every build signed with one stable identity read from the environment, and produces the universal (arm64 + x86_64) app the MVP ships.

## Scope

- Follow `docs/runbooks/signing-identity.md`: self-signed "Tadidy Dev" code-signing certificate in the login keychain, or a Developer ID; fix the runbook where it is wrong or incomplete.
- `tauri.conf.json`: `bundle.macOS.signingIdentity` left `null` so Tauri takes `APPLE_SIGNING_IDENTITY` from the environment; `bundle.macOS.minimumSystemVersion` `"13.0"`; no sandbox entitlement; `bundle.targets` = `app` + `dmg`.
- `src-tauri/Info.plist`: add `NSHumanReadableCopyright` (keep `LSUIElement`).
- `package.json` script `build:universal` = `tauri build --target universal-apple-darwin`.
- A guard test `scripts/build-config.test.mjs` (`node:test`) that reads `tauri.conf.json`, `Info.plist` and `package.json`, so the configuration cannot drift silently.
- Manual QA proving the designated requirement is identical across two builds, and that the Accessibility grant and the Keychain item survive a rebuild.

## Out of scope

- Notarization, DMG layout, release tags (skill `release-dmg`, later).
- The updater signing key (P2, SYS-04).

## Acceptance criteria

- [ ] Given the repository, when `node --test scripts/build-config.test.mjs` runs, then it passes, and adding a literal `signingIdentity` value makes it fail.
- [ ] Given `APPLE_SIGNING_IDENTITY="Tadidy Dev"`, when `pnpm build:universal` runs, then `codesign -dv --verbose=2` on `Tadidy.app` shows `Authority=Tadidy Dev` (not `adhoc`) and `codesign --verify --deep --strict` succeeds.
- [ ] Given two consecutive universal builds with a code change between them, when `codesign -d -r- Tadidy.app` is run on each, then both designated requirements are identical.
- [ ] Given the universal build, when `lipo -archs Tadidy.app/Contents/MacOS/*` runs, then it prints `x86_64 arm64`.
- [ ] Given Accessibility granted to build N, when build N+1 is installed over it and launched, then `check_accessibility` still returns `true` (needs TAD-005).
- [ ] Given the database key created by build N, when build N+1 launches, then the history opens without a Keychain prompt (needs TAD-007).
- [ ] Given the repository, then no certificate, `.p12` or identity name of a real person is committed (gitleaks clean).

## Verification

- `node --test scripts/build-config.test.mjs` → all pass
- `pnpm build:universal` → `src-tauri/target/universal-apple-darwin/release/bundle/macos/Tadidy.app` and a `.dmg`
- `codesign -d -r- src-tauri/target/universal-apple-darwin/release/bundle/macos/Tadidy.app` → same output on two builds
- `scripts/check.sh` → exit 0

## Security

- `APPLE_SIGNING_IDENTITY` and any notarization secret live in the shell profile or a password manager; `.gitignore` already blocks `*.p12` and `*.cer`.

## Risks

- Accessibility permission lost on every rebuild (spec risk) → stable identity from now on; in development, run the signed `.app`, not `cargo run`, when testing auto-paste.
- Universal build fails on the x86_64 half of SQLCipher/OpenSSL → both targets are in `rust-toolchain.toml`; record any fix in `docs/solutions/`.
- A self-signed certificate is not trusted for code signing by default → follow the runbook; if `codesign` refuses it, record the fix in the runbook.
