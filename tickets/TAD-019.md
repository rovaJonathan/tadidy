# TAD-019 — MVP acceptance pass

> Phase 1 · P0 · repo

## Context

Phase 1 ends when Tadidy is "usable every day for text" (roadmap). This ticket checks every MVP acceptance criterion of the spec and the measurable non-functional requirements on the real, signed, universal build, and records the evidence. It finds problems; it does not fix them.

## Scope

- Build with `pnpm build:universal` (signed with `APPLE_SIGNING_IDENTITY`, TAD-008), install in `/Applications`, grant Accessibility.
- Run the 10 criteria of `docs/spec/05-quality.md#mvp-acceptance` in order, on a clean history (delete `tadidy.db` and its Keychain item first) and with synthetic clips only.
- Measure:
  - idle CPU over 10 min in Activity Monitor (criterion 10, < 0.5 %);
  - popover and Quick Panel opening time, 10 openings each (< 100 ms; screen recording at 60 fps or a timing log from the show path to the first `panel://shown` handling);
  - search over 10 000 clips (< 50 ms; reuse `src-tauri/tests/search_perf.rs` numbers and one manual check with a seeded database);
  - RAM with both windows used (< 120 MB) and the `.app` binary size (< 15 MB), recorded but not part of the 10 criteria.
- Re-run the manual QA sections of TAD-003 … TAD-018 that need the signed build (TAD-008 rebuild steps included).
- Record a results table (criterion, result ✅/❌, measure, note, follow-up ticket) in the pull request and under `### TAD-019 — MVP acceptance` in `docs/guides/manual-qa.md`.
- Every ❌ becomes a new ticket created with `ticket-create` (phase 1, linked in the table); it is not fixed in this ticket.

## Out of scope

- Fixing any failure (new tickets); phase 2 features; notarization and release (skill `release-dmg`).

## Acceptance criteria

- [ ] Given the signed universal build, then each of the 10 MVP criteria has a ✅ or ❌ row with the measure or observation that supports it.
- [ ] Given criterion 10, then the idle CPU value comes from a 10-minute observation and is written with its unit.
- [ ] Given the opening-time measure, then 10 values per window are recorded with their median.
- [ ] Given any ❌, then a new `todo` ticket exists for it, linked from the table, and this ticket contains no fix.
- [ ] Given the table, then it holds no real clipboard content (synthetic texts only) and no screenshot shows real content.

## Tests

**Unit** — none (no code).
**Integration** — `cargo test --manifest-path src-tauri/Cargo.toml --test search_perf` as the automated evidence for the search criterion.
**UI / end-to-end** — `pnpm e2e` (whole suite) passes on the tested commit.
**Manual** — `### TAD-019 — MVP acceptance` in `docs/guides/manual-qa.md`: the 10 criteria and the measurements, on the signed build.

## Verification

- `pnpm build:universal` → signed `Tadidy.app` and `.dmg` (`codesign -dv` shows the stable identity)
- `cargo test --manifest-path src-tauri/Cargo.toml --test search_perf` → passes
- `pnpm e2e` → all pass
- `node scripts/tickets.mjs check` → valid (new follow-up tickets included)
- `scripts/check.sh` → exit 0

## Security

- Use synthetic clips; clear the test history afterwards; screenshots and recordings show synthetic text only.

## Risks

- Accessibility or Keychain lost between builds skews criteria 3, 4 and 7 → build once, install once, then test.
- Criterion 7 needs a real restart → plan it last, with "Launch at login" checked.
- Activity Monitor rounding hides small CPU values → also note `top -l` samples for the Tadidy process.
