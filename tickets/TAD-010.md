# TAD-010 — Clipboard watcher for text clips

> Phase 1 · P0 · core

## Context

macOS sends no notification when the clipboard changes, so Tadidy polls `changeCount` (spec *Watcher*). This is the heart of "lose nothing": every text copy becomes a clip, deduplicated, with its source app, written to the database before the front is told. The paster (TAD-015) relies on it ignoring Tadidy's own writes.

## Scope

- `src-tauri/src/platform/idle.rs`: `trait IdleProbe: Send + Sync { fn seconds_since_last_input(&self) -> f64; }` + `FakeIdle` in `platform/fakes.rs`; `src-tauri/src/macos/idle.rs`: `CgIdleProbe` (`CGEventSourceSecondsSinceLastEventType`, combined session state, any input event).
- `src-tauri/src/clock.rs`: `trait Clock { fn now_ms(&self) -> i64; }`, `SystemClock`, `FixedClock` (tests).
- `src-tauri/src/capture.rs` (pure): `text_clip(text_bytes, source: Option<&SourceApp>, now) -> Option<NewClip>` — valid UTF-8 only, ignores empty or whitespace-only text, `kind = text`, `plain_text` = text, `preview` = first 300 characters, `content_hash` of the UTF-8 bytes, one `public.utf8-plain-text` representation, `byte_size`.
- `src-tauri/src/watcher.rs`: `Watcher` built from `Arc<dyn Pasteboard>`, `Arc<dyn Workspace>`, `Arc<dyn IdleProbe>`, `Db`, `HistoryLimit` (from `AppState`), `Arc<dyn EventSink>`, `Arc<dyn Clock>`:
  - on start, remembers the current change count **without** capturing (no bump of the last clip at every launch);
  - `tick() -> Result<TickOutcome, WatcherError>`: unchanged → `Unchanged`; otherwise remember the new count, then:
    1. types contain `app.tadidy.internal` → hash the plain text, `move_to_top`, emit `clips://changed { updated }`, stop (CAP-12);
    2. read the frontmost app (CAP-08);
    3. no `public.utf8-plain-text` or `capture::text_clip` returns `None` → `Ignored`;
    4. if the source app's icon is not in `app_icons`, fetch it with `Workspace::app_icon_png` and store it;
    5. `insert_or_bump`, then `enforce_limit(limit.get())`, in one transaction (the database is written **before** the event);
    6. emit `clips://changed` with `added` or `updated`, and `removed` when the limit deleted clips.
  - `poll_interval(idle_secs) -> Duration`: 300 ms, or 1 s once idle ≥ 300 s;
  - `spawn(self) -> WatcherHandle`: thread `tadidy-watcher`, stop flag; errors are logged with their code and the loop continues.
- Started in `setup` once the database is open (not started when the database is unavailable).

## Out of scope

- Rich text, images, files, URL detection (CAP-03…06, phase 2); excluded apps (CAP-10) and concealed types (CAP-11), both P1; size limits (CAP-13).
- History-size setting (TAD-011 feeds `HistoryLimit`); the list UI (TAD-013).

## Acceptance criteria

- [ ] Given the watcher starts while the pasteboard holds text, then no clip is created.
- [ ] Given an unchanged change count, when `tick` runs, then it returns `Unchanged` and reads neither types nor data.
- [ ] Given text copied from an app `com.example.editor`, when `tick` runs, then one clip of kind `text` exists with that source bundle and name, the icon is stored once in `app_icons`, and `clips://changed { added }` is emitted after the row is committed.
- [ ] Given the same text copied again, then the existing clip is bumped (`copy_count = 2`, first in the list) and `clips://changed { updated }` is emitted.
- [ ] Given a pasteboard write that carries `app.tadidy.internal`, then no clip is created, the matching clip moves to the top with an unchanged `copy_count`.
- [ ] Given empty, whitespace-only or non-UTF-8 text, or no plain-text type, then `tick` returns `Ignored` and nothing is written.
- [ ] Given `HistoryLimit` set to 10 and 10 clips, when an 11th text is copied, then the oldest unpinned clip is deleted and its id is in `removed`.
- [ ] Given idle time of 299 s then 300 s, then `poll_interval` returns 300 ms then 1 s.
- [ ] Given a clip containing a canary string, when it is recorded, then no log line contains the canary.
- [ ] Given the signed app, when text is copied in TextEdit, then the clip is in the database in less than 500 ms (MVP criterion 1, measured in manual QA).

## Tests

**Unit** — `capture::tests` (UTF-8, whitespace, 300-character preview with multi-byte characters, hash); `watcher::tests` (each criterion above with fakes); `poll_interval`.
**Integration** — `watcher::tests` use a real encrypted temporary database through `Db`.
**UI / end-to-end** — none.
**Manual** — `### TAD-010`: copy in TextEdit → clip present with source TextEdit (inspect through the app logs: id, kind, size only); copy the same text → one clip; leave the Mac idle 5 min → Activity Monitor shows the poll slowing (CPU < 0.5 %); the `clip recorded` log line (it carries the elapsed time since the change was seen) appears less than 500 ms after the copy.

## IPC

- Event `clips://changed` with `ClipsChanged { added?, updated?, removed? }` (type from TAD-009).

## Security

- Logs carry clip id, kind, byte size and duration only; a test enforces it with a canary.
- Until CAP-10/CAP-11 land (phase 2), passwords copied from a password manager are recorded (encrypted): say so in the pull request description.

## Risks

- Polling and battery → adaptive interval and only `change_count` is read while nothing changes.
- A database error kills the thread → errors are logged and the loop goes on; the thread never panics (`unwrap` denied).
- Autorelease leaks on the watcher thread → the `macos/` calls already wrap an `autoreleasepool` (TAD-004).
