# TAD-014 — Keyboard navigation and clip actions

> Phase 1 · P0 · ui

## Context

The promise is "shortcut, a few letters, Return" in under 2 seconds: the browser must be fully usable without a mouse (QPN-04). This ticket centralizes the MVP shortcuts in `src/lib/keyboard.ts` and turns them into actions of the clip browser. Paste and copy are forwarded to the host as callbacks, wired to the real commands in TAD-016.

## Scope

- `src/lib/keyboard.ts`: pure `resolveKey(event, context) -> BrowserAction | null`, `context = { searchFocused, searchEmpty, inputHasSelection, dialogOpen }`. MVP map (spec shortcut table):
  - `↑` / `↓` → `select-previous` / `select-next` (also while the search has focus);
  - `Return` → `paste`; double-click on a row → `paste` (PST-01);
  - `⌥Return` and `⌘C` → `copy` (PST-02); `⌘C` stays a normal text copy when the search input has a text selection;
  - `⌘⌫` → `delete` (HIS-05);
  - `Esc` → `escape`: clears the search when it is not empty, otherwise closes;
  - `⌘F` or any printable character without `⌘`/`⌃` → `focus-search` (the character is inserted into the search);
  - `⌘,` → `open-preferences`;
  - while a dialog is open, only the dialog handles keys.
- `ClipBrowser.svelte` handles the actions: selection moves and scrolls into view (bounded, no wrap), single click selects; `delete` opens `#dialog-delete-clip` when the `confirmBeforeDelete` prop is `true` (default), otherwise deletes at once with `deleteClips([id])`; after a delete the selection stays at the same index.
- `DeleteClipDialog.svelte`: `#dialog-delete-clip`, `role="alertdialog"`, texts, buttons and the "Don’t ask again" checkbox verbatim from the prototype; `Return` confirms, `Esc` cancels (and does not close the window); confirming with the box checked calls `ondisableconfirm()`.
- New props of `ClipBrowser`: `confirmBeforeDelete: boolean`, `onpaste(id)`, `oncopy(id)`, `onclose()`, `onopenpreferences()`, `ondisableconfirm()`.

## Out of scope

- Calling `paste_clip` / `copy_clip` and hiding the window (TAD-015, wired by TAD-016); reading `confirmBeforeDelete` from the settings (TAD-016).
- P1 keys: `⇧Return` (plain text), `⌘1`–`⌘9`, `Space` (preview), `⌘P`, `⌘S`, `⌘O`, `⌘K`, `Tab` / `⇧Tab`.

## Acceptance criteria

- [x] Given the search focused with "sel" typed, when `↓` then `Return` are pressed, then `onpaste` is called with the id of the second row.
- [x] Given a selected row, when `⌥Return` or `⌘C` (no text selected in the search) is pressed, then `oncopy` is called with its id; with text selected in the search, `⌘C` copies the text and `oncopy` is not called.
- [x] Given the first row selected, when `↑` is pressed, then the selection stays on the first row; at the last loaded row, `↓` loads the next page when there is one.
- [x] Given `confirmBeforeDelete = true`, when `⌘⌫` is pressed, then `#dialog-delete-clip` opens; `Return` deletes through `delete_clips`, `Esc` closes the dialog only.
- [x] Given the dialog confirmed with "Don’t ask again" checked, then the clip is deleted and `ondisableconfirm` is called once.
- [x] Given `confirmBeforeDelete = false`, when `⌘⌫` is pressed, then `delete_clips` is invoked at once and no dialog opens.
- [x] Given a non-empty search, when `Esc` is pressed, then the search is cleared; pressed again, then `onclose` is called.
- [x] Given focus on the list, when the letter `a` is typed, then the search gets focus and contains "a".
- [x] Given `⌘,`, then `onopenpreferences` is called.
- [x] Given a double-click on a row, then `onpaste` is called with its id.

## Risks

- `⌘C` stealing the normal copy of the search text → rule on `inputHasSelection`, tested.
- Key handling scattered across components → every key goes through `resolveKey` (AGENTS.md §14).
- WebKit sends `keydown` with `isComposing` during IME input → ignore composing events.
