# TAD-028 — Extract the shared alert dialog shell from the three confirmation dialogs

> Phase 1 · P2 · ui · Discovered in: TAD-022 (review of the pull request)

## Context

`DeleteClipDialog`, `ClearHistoryDialog` and (since TAD-022) `ResetHistoryDialog` repeat the same focus trap (`handleKey`, `moveFocus`), the same `onkeydown` `stopPropagation` and about 80 lines of alert CSS. The hosts (`ClipBrowser`, `Popover`) also repeat the code that routes keys to an open dialog. A fix to the trap or the styling has to be made in three or more places.

## Scope

- One shared alert shell (focus trap, key handling, alert styles) with the icon, texts and buttons passed in.
- The three dialogs rebuilt on it, with no change of behaviour, ids or texts.
- The key routing of the hosts shared where it is the same.

## Out of scope

- Any new dialog, text or visual change.
- The Preferences window and the toast.

## Steps

- [ ] Red tests: the shell on its own (Tab cycle, Esc, Enter outside a button, Return/Space on a focused button).
- [ ] Extract the shell; rebuild the three dialogs on it; their existing tests stay green unchanged.
- [ ] Open the pull request to `main`.
