# TAD-024 — Mock check_accessibility in every end-to-end spec

> Phase 1 · P2 · ui · Discovered in: TAD-019 (the Vite server log of `pnpm e2e`)

## Context

`pnpm e2e` passes (42 tests), but its Vite log fills with `[Unhandled rejection] Error: IPC command not mocked: check_accessibility`, raised from `PermissionBanner.svelte` through `checkAccessibility` in `src/lib/api.ts`. `clear-history.spec.ts` and `hosts.spec.ts` mock the command; `clip-browser.spec.ts`, `keyboard.spec.ts`, `preferences.spec.ts` and `smoke.spec.ts` do not. The noise hides real errors in the log, and a spec that depends on the banner's state silently gets none.

## Scope

- Put `check_accessibility: true` in the shared default responses of the e2e IPC mock (`e2e/support/`) so every spec gets it, and drop the per-spec copies that become redundant.
- Make the e2e run fail on an unmocked IPC command instead of logging it (the mock throws and the test reads the page errors), so the gap cannot come back unseen.

## Out of scope

- Changing `PermissionBanner.svelte` or `src/lib/api.ts` behaviour.
- Adding new e2e flows.

## Steps

- [ ] Red: an e2e check that fails when any IPC command is called without a mock (a deliberately unmocked command in a throwaway spec, then removed); commit `test(TAD-024): fail on an unmocked IPC command`.
- [ ] Green: default `check_accessibility` in `e2e/support/`; remove redundant per-spec entries.
- [ ] Run `pnpm e2e` and read the log: no `IPC command not mocked` line.
- [ ] Open the pull request to `main`.
