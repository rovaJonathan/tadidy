# TAD-026 — Open the Quick Panel on the first launch with a fresh database

> Phase 1 · P1 · core · Discovered in: TAD-019 (MVP criterion 3 on the first launch of a fresh install)

## Context

On the signed universal build, installed in `/Applications` over a deleted data folder and Keychain item (a true first run), the owner pressed the Quick Panel shortcut (`⌘⇧V`) and the panel did not open. After quitting and starting Tadidy again, the same shortcut opened it. So the first run after creating the database does not leave the shortcut working, and a first-time user would conclude the app is broken. The cause is unknown; this ticket finds it.

The start-up path to look at: the stored settings do not exist yet on a fresh database, the shortcut is registered from them, and `shortcuts::switch` records a `ShortcutStatus` whose error is only shown in Preferences › Shortcuts.

## Scope

- Reproduce on the signed build from a clean state (no `~/Library/Application Support/app.tadidy/`, no `app.tadidy` / `database-key` Keychain item): first launch, press the shortcut, then restart and press it again. Read `RUST_LOG=tadidy_lib=debug` output (launch with `open -a /Applications/Tadidy.app --stderr <file> --env RUST_LOG=tadidy_lib=debug`).
- Find why the first launch does not register or handle the shortcut (settings not stored yet, registration before the main run loop, a state set only after the first write…).
- Fix it, and make a failed registration at start-up visible in the logs (code only, never a path or clip content).

## Out of scope

- A shortcut that another app already holds (known limit, TAD-017 step 14).
- Changing the default shortcut.
