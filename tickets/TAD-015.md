# TAD-015 — Paste and copy commands

> Phase 1 · P0 · full

## Context

Pasting back into the app the user was in is the reason Tadidy exists (PST-01). The sequence must put the clip on the pasteboard, give focus back to the right app and send `⌘V` — or, without the Accessibility permission, only copy and say so with a banner (PST-02, SYS-03). The focus-stealing risk of the spec is closed here for both windows.

## Scope

- `Workspace` gains `fn activate(&self, app: &SourceApp) -> Result<(), PlatformError>` (`NSRunningApplication.activateWithOptions` by pid in `macos/workspace.rs`; `FakeWorkspace` records it).
- `AppState.last_active_app: Mutex<Option<SourceApp>>`, set from `Workspace::frontmost_app` just **before** the popover is shown (`windows.rs`).
- `src-tauri/src/paster.rs`: `Paster` built from `Arc<dyn Pasteboard>`, `Arc<dyn KeySender>`, `Arc<dyn AccessibilityProbe>`, `Arc<dyn Workspace>`, a `WindowHider` trait (`hide(origin)`, implemented on `AppHandle` in `windows.rs`) and an injectable delay (50 ms, zero in tests):
  - `PasteOrigin::{Popover, Panel}` from the calling window's label (other labels → `AppError { code: "invalid_window" }`);
  - `paste(clip, mode, origin) -> PasteResult`: (1) write the clip's representations (`PasteMode::Plain` → only `public.utf8-plain-text`) plus `app.tadidy.internal`; (2) if not trusted → return `CopiedOnly`, window left open; (3) hide the window; (4) origin `Popover` → re-activate `last_active_app`; (5) wait; (6) `send_paste`; return `Pasted`;
  - `copy(clip, origin)`: step 1, then hide the window (and re-activate for the popover), no key event.
- `PasteMode` (`default` | `plain`) and `PasteResult` (`pasted` | `copied_only`) with ts-rs.
- `storage::clips::mark_used(conn, id, now)` sets `last_used_at` for paste and copy.
- `AccessibilityMonitor` in `paster.rs`: keeps the last known trust value; checked at every paste and every window show; emits `accessibility://changed` with `AccessibilityChanged { trusted: bool }` (ts-rs) when it changes.
- Commands `paste_clip(id, mode) -> PasteResult` and `copy_clip(id) -> ()`; unknown id → `not_found`.
- Front: wrappers `pasteClip(id, mode)`, `copyClip(id)`, `onAccessibilityChanged(cb)`; `src/lib/components/PermissionBanner.svelte` — `#banner-accessibility` with `#btn-enable-accessibility` (calls `openAccessibilitySettings()`), texts verbatim from the prototype; visible when `checkAccessibility()` on mount or the last event says `false`. TAD-016 places it in the browser.

## Out of scope

- `⇧Return` and the "always plain text" option (PST-03, PST-05, P1); restoring the previous clipboard (P2); paste many (P2).
- Placing the banner and wiring `onpaste` / `oncopy` in the windows (TAD-016).

## Acceptance criteria

- [ ] Given trust and origin `Popover`, when `paste_clip` runs, then the calls happen in the order write (with marker) → hide → activate(previous app) → wait → `⌘V`, and the result is `pasted`.
- [ ] Given trust and origin `Panel`, then no app is activated and the order is write → hide → wait → `⌘V`.
- [ ] Given no trust, then only the write happens, the result is `copied_only`, and `accessibility://changed { trusted: false }` is emitted once (not again on the next paste).
- [ ] Given `copy_clip`, then the representations and the marker are written, the window hides, no key event is sent.
- [ ] Given a paste or a copy, then `last_used_at` of the clip is set, and the watcher (TAD-010) moves the clip to the top without creating a new one.
- [ ] Given an unknown id, then `paste_clip` fails with `not_found` and the pasteboard is untouched.
- [ ] Given `checkAccessibility()` resolves `false`, then `#banner-accessibility` is visible; clicking `#btn-enable-accessibility` invokes `open_accessibility_settings`; an event `{ trusted: true }` hides it.
- [ ] Given the probe with Accessibility granted, TextEdit recorded as frontmost and Finder clicked afterwards, when it pastes with origin `Popover`, then TextEdit is re-activated and receives the text; with origin `Panel` and TextEdit still active, the text lands in TextEdit (Safari text field: same).

## IPC

- `paste_clip(id: string, mode: PasteMode) -> PasteResult` · `pasteClip(id, mode)`
- `copy_clip(id: string) -> void` · `copyClip(id)`
- Event `accessibility://changed` (`AccessibilityChanged { trusted }`) · `onAccessibilityChanged(cb)`

## Security

- Clip data goes from the database to the pasteboard in Rust only; the webview sends an id.
- Logs: clip id, mode, result and duration, never the content.

## Risks

- The popover steals focus and `⌘V` goes to Tadidy (spec risk, high) → remember the frontmost app before showing the popover and re-activate it before sending; the Quick Panel never activates.
- 50 ms is too short on a loaded machine → delay is a constant in one place; if QA shows misses, raise it and note it in `PROGRESS.md`.
- Accessibility lost after a rebuild → QA only on the signed build (TAD-008).
