# TAD-020 — Add the review-pr skill and run parallel sessions in git worktrees

> Phase 0 · P1 · repo · Discovered in: TAD-001 (a second session started while TAD-001 was being implemented in the main folder)

## Context

Two agent sessions sharing the main folder switch branches and edit files under each other's feet. A session that starts while the main folder is busy must work in its own git worktree. The human also wants an agent code review of a pull request, posted on GitHub, that `address-pr` can then process like any other review.

## Scope

- `scripts/worktree.mjs` (`node:test` tested): `status` (main folder busy or not), `add <branch>` (worktree in `../tadidy-worktrees/<branch>` from `origin/main`, dependencies installed), `review <N>` (detached worktree `../tadidy-worktrees/review-pr-<N>` on the pull request head), `remove <name>`, `prune` (removes clean worktrees whose pull request is merged or closed, and review worktrees). `add` and `review` refuse to run when `core.hooksPath` is relative, because hooks would then be skipped silently in a worktree.
- The parallel-session rule: the main folder is busy when it is not on `main` or has uncommitted changes; a session that would work on another ticket then works in a worktree. Written in `docs/guides/parallel-sessions.md`, AGENTS.md §8, and the skills `tadidy-session`, `ticket-claim`, `ticket-problem`, `address-pr`, `release-dmg`.
- Skill `review-pr`: reads the pull request and its ticket, runs the checks in a review worktree, reviews the diff against AGENTS.md and the `self-review` checklist, verifies each finding, posts one GitHub review (`COMMENT`) with inline comments, removes the worktree. Listed in AGENTS.md §16.
- `core.hooksPath` set to the absolute hooks directory of the common git dir (README, ADR 0004 note).
- `.claude/settings.json`: `../tadidy-worktrees` as an additional directory, read-only `worktree.mjs status` allowed.

## Out of scope

- Making the end-to-end port configurable so two worktrees can run `pnpm e2e` at the same time (port 1420 is shared): documented as a trap; a separate ticket if it becomes a need.
- Sharing the Cargo `target/` directory between worktrees.

## Acceptance criteria

- [x] Given the main folder on a `tad-xxx` branch or with uncommitted changes, when `node scripts/worktree.mjs status` runs, then it reports `busy: true`.
- [x] Given a branch name, when `node scripts/worktree.mjs add <branch>` runs, then `../tadidy-worktrees/<branch>` exists on that branch, based on `origin/main` (or `main` without a remote).
- [x] Given a relative `core.hooksPath`, when `add` or `review` runs, then it fails and prints the command that fixes it.
- [x] Given worktrees whose pull request is merged or closed, a review worktree and an open one, when `prune` selects, then only the first two kinds are selected.
- [x] Given AGENTS.md, when `node scripts/repo-check.mjs` runs, then `review-pr` is listed and valid.

## Tests

**Unit** — `scripts/worktree.test.mjs` (`node:test`), including `add` on a temporary repository.
**Manual** — an invalid commit message is refused inside a worktree; `review-pr` run on a real pull request.

## Verification

- `node --test scripts/worktree.test.mjs` → all pass
- `node scripts/repo-check.mjs` → no error
- `scripts/check.sh` → exit 0

## Risks

- A relative `core.hooksPath` (`.git/hooks`) points at a file inside a worktree, so every hook is skipped silently → absolute path, and `worktree.mjs` refuses to create a worktree otherwise.
- Playwright reuses any server on port 1420 (`reuseExistingServer`) → two worktrees running `pnpm e2e` together would test each other's code: run end-to-end tests in one worktree at a time.
- The agent posts the review with the human's GitHub account → the review is `COMMENT` only, never `APPROVE` or `REQUEST_CHANGES`, and its body says it comes from the agent.
