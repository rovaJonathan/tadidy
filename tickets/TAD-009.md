# TAD-009 — Clips schema and repository

> Phase 1 · P0 · core

## Context

The watcher (TAD-010), the settings (TAD-011), the list and search (TAD-012) and the paster (TAD-015) all read and write clips. This ticket creates the full data model of the spec in one migration, so phase 2 (rich text, images, files, pinned clips, snippets, collections, excluded apps) adds no table rewrite, and the repository functions the MVP needs.

## Scope

- Migration `0002_clips.sql` with exactly the spec's data model: `collections` (first, for the foreign key), `clips`, `representations`, `thumbnails`, `excluded_apps`, `app_icons`, `clips_fts` (FTS5, `content='clips'`, `content_rowid='rowid'`, `tokenize='unicode61 remove_diacritics 2'`), indexes `idx_clips_recent`, `idx_clips_kind`, plus `idx_clips_last_copied ON clips(last_copied_at DESC, id DESC)` for the unfiltered newest-first list.
- FTS sync triggers: `clips_ai` (AFTER INSERT), `clips_ad` (AFTER DELETE, `'delete'` command), `clips_au` (AFTER UPDATE **OF** `plain_text, title, source_name` only, so bumps do not rewrite the index).
- `src-tauri/src/clip.rs`:
  - `ClipKind` (`text`, `rich`, `image`, `file`, `url`, `color`; `#[derive(TS)]`, serde lowercase);
  - `NewClip { kind, content_hash, plain_text, preview, source_bundle, source_name, byte_size, representations: Vec<Representation>, now: i64 }` (`Representation` from `platform::pasteboard`);
  - `ClipRecord` (one row of `clips`) and `ClipWithRepresentations`;
  - `content_hash(primary: &[u8]) -> String` (SHA-256, lowercase hex);
  - `HistoryLimit` (`Arc<AtomicU32>`, `0` = unlimited; `get() -> Option<u32>`, `set(Option<u32>)`), `DEFAULT_HISTORY_SIZE = 500`; one instance in `AppState`.
- `ClipsChanged { added: Option<String>, updated: Option<String>, removed: Option<Vec<String>> }` (ts-rs, camelCase) in `src-tauri/src/events.rs`; an all-empty payload means "reload".
- `src-tauri/src/storage/clips.rs` (functions on `&rusqlite::Connection`, parameters only):
  - `insert_or_bump(conn, &NewClip) -> Result<InsertOutcome, StorageError>` — UUID v7 id; on `content_hash` conflict: `last_copied_at = now`, `copy_count + 1`, source app updated to the latest copier; `InsertOutcome::{Inserted(id), Bumped(id)}` (CAP-09);
  - `move_to_top(conn, content_hash, now) -> Result<Option<String>, _>` — only `last_copied_at` changes (used for Tadidy's own writes, CAP-12);
  - `list_recent(conn, cursor: Option<&Cursor>, limit) -> Result<Vec<ClipRecord>, _>` — `last_copied_at DESC, id DESC`; `Cursor { last_copied_at, id }` with `encode()` / `decode(&str)`;
  - `get(conn, id) -> Result<Option<ClipWithRepresentations>, _>`;
  - `delete(conn, ids) -> Result<Vec<String>, _>` (ids actually removed);
  - `clear(conn, keep_pinned) -> Result<u32, _>` (HIS-06);
  - `enforce_limit(conn, max: Option<u32>) -> Result<Vec<String>, _>` — deletes the oldest non-pinned clips beyond `max`; pinned clips (snippets included) do not count (HIS-02);
  - `count(conn) -> Result<u32, _>`;
  - `incremental_vacuum(conn)`, called at the end of `delete`, `clear` and `enforce_limit` when rows were removed.
- `src-tauri/src/storage/app_icons.rs`: `has(conn, bundle_id)`, `put(conn, bundle_id, png)`, `get(conn, bundle_id)`.

## Out of scope

- Search, `ClipSummary`, `Page` and IPC commands (TAD-012); the watcher (TAD-010); settings (TAD-011).
- Pin, snippet, collection, thumbnail and exclusion operations (phase 2): tables only.

## Acceptance criteria

- [ ] Given migrations run on a new database, then every table, index and trigger of *Database* exists and `user_version` is 2; running them again changes nothing.
- [ ] Given a new clip, when it is inserted, then it is returned `Inserted` with `copy_count = 1` and `created_at = last_copied_at = now`.
- [ ] Given the same `content_hash` inserted again later, then the result is `Bumped(same id)`, one row exists, `copy_count = 2` and it is first in `list_recent`.
- [ ] Given `move_to_top` on an existing hash, then `last_copied_at` changes and `copy_count` does not; on an unknown hash it returns `None`.
- [ ] Given 25 clips and `limit = 10`, when `list_recent` is paged with the returned cursor, then pages are 10, 10, 5, ordered, without duplicates.
- [ ] Given 12 clips of which 2 are pinned and `enforce_limit(Some(10))`, then the 2 oldest unpinned clips are deleted, both pinned clips remain, and their representations are gone (cascade).
- [ ] Given `enforce_limit(None)`, then nothing is deleted.
- [ ] Given `clear(keep_pinned = true)` then `clear(false)`, then the counts returned match the rows removed and only pinned clips survive the first call.
- [ ] Given a clip whose `plain_text` contains "café", when `clips_fts` is queried for `cafe`, then it matches; after `delete`, it no longer matches.
- [ ] Given a bump, then `clips_fts` is not rewritten (the update trigger only fires on the three indexed columns).

## Security

- Test fixtures are synthetic strings; no real clipboard content.
- Errors carry ids and codes, never `plain_text` or `preview`.

## Risks

- `clips_fts` follows the implicit `rowid` of `clips`, which a full `VACUUM` may renumber → only `PRAGMA incremental_vacuum` is used; any future full `VACUUM` must be followed by `INSERT INTO clips_fts(clips_fts) VALUES('rebuild')`.
- Cascades silently skipped without `PRAGMA foreign_keys = ON` → set by `storage::open` (TAD-007); a test checks the cascade.
- `INSERT … ON CONFLICT … RETURNING id` needs SQLite ≥ 3.35 → bundled SQLCipher is newer; the bump test covers it.
