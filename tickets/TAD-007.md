# TAD-007 — Encrypted database foundation

> Phase 0 · P0 · core

## Context

Phase 0 spike "SQLCipher + Keychain": the history must be encrypted at rest with a key that lives only in the Keychain and in memory (AGENTS.md §2). Building SQLCipher with its vendored OpenSSL as a universal binary is a listed risk. Every storage ticket (TAD-009 onwards) builds on `storage::open`.

## Scope

- `rusqlite` with feature `bundled-sqlcipher-vendored-openssl`, `rusqlite_migration`.
- `src-tauri/src/crypto.rs`:
  - `DbKey([u8; 32])`, generated from the OS RNG (`getrandom`); `Debug` prints `DbKey(<redacted>)`; no `Serialize`;
  - `trait KeyStore: Send + Sync { fn get(&self) -> Result<Option<DbKey>, KeyStoreError>; fn set(&self, key: &DbKey) -> Result<(), KeyStoreError>; }` and `FakeKeyStore` (in-memory, public for integration tests);
  - `load_or_create_key(store: &dyn KeyStore, db_exists: bool) -> Result<DbKey, StorageError>`: key found → returned; no key and no database → generate, store, return; no key but the database exists → `StorageError::KeyMissing`.
- `src-tauri/src/macos/keychain.rs`: `KeychainKeyStore` (`security-framework`), generic password, service `app.tadidy`, account `database-key`, accessibility `AfterFirstUnlockThisDeviceOnly`.
- `src-tauri/src/storage/mod.rs`:
  - `StorageError` (`thiserror`): `KeyMissing`, `WrongKey` (SQLCipher "file is not a database"), `Migration`, `KeyStore`, `Sqlite`; mapped to `AppError` codes `storage_key_missing`, `storage_wrong_key`, `storage_error`;
  - `Db` = `Arc<Mutex<rusqlite::Connection>>` newtype with `with_conn(|c| …)`;
  - `open(path: &Path, key: &DbKey) -> Result<Db, StorageError>`: `PRAGMA key` with the raw-key form `x'<64 hex>'` as the first statement, check with `SELECT count(*) FROM sqlite_master` (→ `WrongKey`), then `PRAGMA auto_vacuum = INCREMENTAL` (before any table exists), `PRAGMA journal_mode = WAL`, `PRAGMA foreign_keys = ON`, then migrations.
- `src-tauri/src/storage/migrations.rs`: `rusqlite_migration::Migrations` built from `include_str!` files; `src-tauri/src/storage/migrations/0001_settings.sql` creates `settings (key TEXT PRIMARY KEY, value TEXT NOT NULL)`.
- `setup`: data dir `~/Library/Application Support/app.tadidy/` (`app.path().app_data_dir()`), file `tadidy.db`, `KeychainKeyStore`, `Db` stored in `AppState`. On `KeyMissing`, the existing file is left untouched, the error code is logged and the app runs without a database.

## Acceptance criteria

- [x] Given a new path and key A, when `open` runs twice, then both succeed and migrations report version 1 with the `settings` table present.
- [x] Given a database created with key A, when it is opened with key B, then `StorageError::WrongKey` is returned.
- [x] Given a database created with key A, when it is opened with no key, then any query fails with "file is not a database".
- [x] Given an opened database, then `PRAGMA journal_mode` is `wal`, `PRAGMA auto_vacuum` is `2` (incremental) and `PRAGMA foreign_keys` is `1`.
- [x] Given an empty `FakeKeyStore` and no database, when `load_or_create_key` runs, then a key is generated, stored, and the same key is returned next time.
- [x] Given an empty key store while the database file exists, when `load_or_create_key` runs, then it returns `StorageError::KeyMissing` and the file's bytes are unchanged.
- [x] Given the real app on first launch, then a Keychain item `app.tadidy` / `database-key` exists and `sqlite3 tadidy.db .tables` fails with "file is not a database".
- [x] Given `pnpm tauri build --target universal-apple-darwin --no-bundle`, then `lipo -archs` on the binary prints `x86_64 arm64`.

## Security

- The key is never written to disk, logged, put in an error message or sent to the webview; it is passed to SQLCipher only.
- Tests use a fixed test key and temporary directories, never the Keychain.

## Risks

- `auto_vacuum` cannot be changed once tables exist → set it right after `PRAGMA key`, before the first migration.
- A passphrase key runs PBKDF2 at every open (slow) → use the raw 32-byte key form `x'…'`.
- Building SQLCipher + OpenSSL for both architectures → the universal build is part of this ticket's verification; record any extra toolchain need in `docs/solutions/`.
- `AfterFirstUnlockThisDeviceOnly` may not apply to the file-based login keychain used by a self-signed app → check the item's attributes in Keychain Access; if the attribute is ignored, note it in `PROGRESS.md` (the item still stays local).
- Keychain access tied to the signature → stable signing (TAD-008); during `pnpm tauri dev`, macOS may ask for the login password once per rebuild.
