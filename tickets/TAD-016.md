# TAD-016 — Popover and Quick Panel host the clip browser

> Phase 1 · P0 · ui

## Context

The clip browser (TAD-013, TAD-014), the paste commands (TAD-015) and the two windows (TAD-003, TAD-006) exist separately. This ticket puts the same browser component in both windows (QPN-06), connects its callbacks to the real commands, and completes the footer (MNU-05). After it, the MVP flow "⌘⇧V, ↓, Return" works end to end.

## Scope

- `src/windows/Popover.svelte` and `src/windows/Panel.svelte` render `<ClipBrowser>` (replacing the placeholders) with:
  - `onpaste(id)` → `pasteClip(id, "default")`; on `copied_only` the window stays open and the banner shows; on `pasted` Rust has already hidden the window;
  - `oncopy(id)` → `copyClip(id)`;
  - `onclose()` → `hideWindow()`;
  - `onopenpreferences()` → `openPreferences()` (TAD-017);
  - `confirmBeforeDelete` from `src/lib/stores/settings.svelte.ts` (TAD-017), kept current by `settings://changed`;
  - `ondisableconfirm()` → `setSettings({ confirmBeforeDelete: false })` ("Don’t ask again" in `#dialog-delete-clip`).
- `onPanelShown` filtered on the window's own label (`popover` or `panel`) → `browser.reset()`: empty search, selection on the first row, list refreshed, search focused.
- `BrowserFooter.svelte`: `#clip-count` and `#btn-preferences` (⚙, `aria-label` from the prototype) laid out as in the prototype; the footer hints show only the MVP actions (`↩ Paste`, `⌥↩ Copy`), the `⇧↩ Plain text` and `⌘K Actions` hints arrive with their P1 tickets; `PermissionBanner` (TAD-015) placed where the prototype puts `#banner-accessibility`.
- The Escape placeholder handlers of TAD-003 / TAD-006 are removed (the browser's `escape` action handles it).
- Error handling: a failed command shows nothing new in the MVP but is logged with its `code` to the console in development only.

## Out of scope

- Quick Panel position options (QPN-03, P1): the panel opens centered on the active screen as set up by TAD-006.
- Tabs, filters, preview, context menu (P1); the preferences window itself (TAD-017).

## Acceptance criteria

- [x] Given `/popover.html` and `/panel.html`, then both render the same `ClipBrowser` with `#search-input`, `#clip-list`, `#clip-count` and `#btn-preferences`.
- [x] Given a selected clip, when `Return` is pressed, then `paste_clip` is invoked with its id and `"default"`.
- [x] Given `paste_clip` resolves `copied_only`, then the window is not hidden by the front and `#banner-accessibility` is visible.
- [x] Given a search typed and the third row selected, when `panel://shown` arrives for this window, then the search is empty, the first row is selected and the search has focus; an event for the other window changes nothing.
- [x] Given `#btn-preferences` is clicked or `⌘,` is pressed, then `open_preferences` is invoked.
- [x] Given "Don’t ask again" checked when confirming a delete, then `set_settings({ confirmBeforeDelete: false })` is invoked.
- [x] Given `confirmBeforeDelete` turned off in the preferences, when `⌘⌫` is pressed in either window, then the clip is deleted without a dialog.
- [x] Given the signed app with Accessibility, when `⌘⇧V`, `↓`, `Return` are pressed in TextEdit, then the 2nd clip is pasted into TextEdit, which keeps focus (MVP criterion 3); the same from the popover returns focus to TextEdit and pastes.
