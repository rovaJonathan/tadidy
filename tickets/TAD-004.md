# TAD-004 — Pasteboard and workspace layer behind traits

> Phase 0 · P0 · core

## Context

Phase 0 spike "read `changeCount` via objc2": the watcher (TAD-010) and the paster (TAD-015) need to read and write `NSPasteboard` and to know the frontmost app. This ticket puts that AppKit code in the thin `macos/` layer behind two traits, so all the logic around it is tested with in-memory fakes (AGENTS.md §9).

## Scope

- `src-tauri/src/platform/mod.rs`: `PlatformError` (`thiserror`), re-exports.
- `src-tauri/src/platform/pasteboard.rs`:
  - `Representation { uti: String, data: Vec<u8> }` (the glossary term, reused by storage and paster);
  - UTI constants `UTI_PLAIN_TEXT = "public.utf8-plain-text"`, `UTI_TADIDY_MARKER = "app.tadidy.internal"`, `IGNORED_TYPES` (the three `org.nspasteboard.*` types of AGENTS.md §3);
  - `trait Pasteboard: Send + Sync { fn change_count(&self) -> i64; fn types(&self) -> Vec<String>; fn read(&self, uti: &str) -> Option<Vec<u8>>; fn write(&self, items: &[Representation]) -> Result<i64, PlatformError>; }` — `write` clears the pasteboard, writes every item in one `NSPasteboardItem`, returns the new change count.
- `src-tauri/src/platform/workspace.rs`:
  - `SourceApp { bundle_id: String, name: String, pid: i32 }`;
  - `trait Workspace: Send + Sync { fn frontmost_app(&self) -> Option<SourceApp>; fn app_icon_png(&self, app: &SourceApp) -> Option<Vec<u8>>; }` — icon rendered as a 64 × 64 px PNG (32 pt @2x).
- `src-tauri/src/platform/fakes.rs` (public, so `src-tauri/tests/` can use them): `FakePasteboard` (in-memory items; `set(items)` bumps the change count like AppKit; records writes), `FakeWorkspace` (settable frontmost app and icons).
- `src-tauri/src/macos/pasteboard.rs`: `NsPasteboard` implementing `Pasteboard` on `NSPasteboard.generalPasteboard` with `objc2-app-kit`; every call wrapped in an `autoreleasepool`.
- `src-tauri/src/macos/workspace.rs`: `NsWorkspace` implementing `Workspace` (`NSWorkspace.frontmostApplication`: `bundleIdentifier`, `localizedName`, `processIdentifier`).
- `src-tauri/src/macos/app_icon.rs`: `NSRunningApplication.icon` → 64 × 64 `NSBitmapImageRep` → PNG bytes.
- Developer probe `src-tauri/examples/pasteboard_probe.rs`: polls every 300 ms and prints change count, types, byte sizes per type and the frontmost app (never the data itself).

## Out of scope

- The polling thread, extraction and storage (TAD-010); writing clips back (TAD-015).
- Reactivating an app (`activateWithOptions`, added to `Workspace` by TAD-015); idle time (TAD-010).

## Acceptance criteria

- [x] Given a `FakePasteboard`, when `set` is called twice, then `change_count` grows by 2 and `types` returns the last items' UTIs.
- [x] Given `write(&[text, marker])`, when it returns, then the result is the new change count and `read(UTI_TADIDY_MARKER)` is `Some`.
- [x] Given text copied in TextEdit, when the probe runs, then the change count increases by one and `public.utf8-plain-text` is listed with the right byte size.
- [x] Given a selection copied in Safari, when the probe runs, then `public.html`, `public.rtf` or `public.utf8-plain-text` are listed and the frontmost app is `com.apple.Safari` / "Safari".
- [x] Given the probe runs for 60 s without copying, then its memory use is stable (no autorelease leak).
- [x] Given any build, then `objc2*` is imported only under `src-tauri/src/macos/`.

## Tests

**Unit** — `platform::fakes::tests::*` (contract of both traits).

## Dependencies

- Rust: `objc2`, `objc2-foundation`, `objc2-app-kit` (enable only the AppKit features used).

## Security

- The probe prints types, sizes and the app name, never the pasteboard data.
- `Representation` does not derive `Debug` with its data: a manual `Debug` prints the UTI and the length only.

## Risks

- Autoreleased objects leak on a background thread without a pool → `autoreleasepool` around every `macos/` call.
- `frontmostApplication` read off the main thread → it is a KVO-updated property kept fresh by the main run loop that Tauri runs; check in manual QA that it changes when switching apps.
- Several `NSPasteboardItem`s (multi-file copies) → `types`/`read` cover the first item now; multi-item reading is part of the phase 2 files ticket (CAP-05).
