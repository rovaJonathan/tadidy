# TAD-005 — Key sender and Accessibility permission

> Phase 0 · P0 · core

## Context

Phase 0 spike "paste via `CGEvent`": auto-paste posts a synthetic `⌘V`, which macOS only allows with the Accessibility (TCC) permission. This ticket proves both on a real app and puts them behind traits, so the paster (TAD-015) can be tested with fakes and fall back to "copy only" when the permission is missing.

## Scope

- `src-tauri/src/platform/keys.rs`: `trait KeySender: Send + Sync { fn send_paste(&self) -> Result<(), PlatformError>; }`.
- `src-tauri/src/platform/accessibility.rs`: `trait AccessibilityProbe: Send + Sync { fn is_trusted(&self) -> bool; fn request_and_open_settings(&self) -> Result<(), PlatformError>; }`.
- Fakes in `src-tauri/src/platform/fakes.rs`: `FakeKeySender` (counts calls, can be set to fail), `FakeAccessibility` (settable trust, records requests).
- `src-tauri/src/macos/keys.rs`: `CgKeySender` posts keyDown + keyUp of virtual key `V` (`kVK_ANSI_V` = 9) with `CGEventFlags::CGEventFlagCommand`, source `CombinedSessionState`, tap `kCGHIDEventTap`.
- `src-tauri/src/macos/accessibility.rs`: `AxProbe` — `is_trusted` = `AXIsProcessTrustedWithOptions` with `kAXTrustedCheckOptionPrompt = false`; `request_and_open_settings` calls it with `prompt = true` (so Tadidy is listed) and opens `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`.
- `AppState` holds `Arc<dyn AccessibilityProbe>` and `Arc<dyn KeySender>` (real ones in `setup`, fakes in tests).
- IPC `check_accessibility() -> bool` and `open_accessibility_settings() -> ()`, with wrappers `checkAccessibility()` / `openAccessibilitySettings()` in `src/lib/api.ts`.
- Developer probe `src-tauri/examples/paste_probe.rs`: prints the trust state, waits 3 s, sends `⌘V` if trusted.

## Out of scope

- The paste sequence (write, hide, reactivate, wait, send) and `PasteResult` (TAD-015).
- The `accessibility://changed` event and the banner (TAD-015); onboarding (SYS-02, phase 2).

## Acceptance criteria

- [x] Given `FakeAccessibility` trusted (then untrusted), when `check_accessibility` is invoked, then it returns `true` (then `false`).
- [x] Given `open_accessibility_settings` is invoked, then the probe's `request_and_open_settings` is called once, and a probe failure becomes `AppError { code: "accessibility_settings_unavailable" }`.
- [x] Given the permission granted to the probe binary and TextEdit frontmost with an insertion point, when the probe sends `⌘V`, then the clipboard text is pasted into TextEdit and TextEdit keeps focus.
- [x] Given the permission not granted, when `is_trusted` is read, then it is `false` and no key event reaches TextEdit.
- [x] Given `request_and_open_settings`, when it runs, then System Settings opens on *Privacy & Security → Accessibility* with the binary listed.
- [x] Given an AZERTY keyboard layout, when the probe sends `⌘V`, then TextEdit pastes (not another shortcut).

## Dependencies

- Rust: `core-graphics`; ApplicationServices FFI for `AXIsProcessTrustedWithOptions` declared by hand in `macos/accessibility.rs` (or `objc2-application-services` if it exposes it).

## Security

- The permission is never requested silently: only `open_accessibility_settings` (user click) prompts.
- The key sender sends exactly `⌘V` and nothing else.

## Risks

- The TCC grant is tied to the binary's signature and is lost on every unsigned rebuild → for the app, QA on the signed build (TAD-008); for the probe, grant the terminal that runs it.
- Virtual key 9 is the physical ANSI `V` position: on layouts where it is not `V` (Dvorak), apps may not see `⌘V` → QA on the user's layouts (QWERTY, AZERTY); if a layout fails, translate the key code with the current input source and open a ticket.
- Modifiers still held by the user (e.g. `⇧` from `⌘⇧V`) would merge into the event → the event carries explicit flags (`Command` only).
