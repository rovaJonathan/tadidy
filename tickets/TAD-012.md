# TAD-012 — Clip list and search commands

> Phase 1 · P0 · full

## Context

The clip browser (TAD-013) needs a paged, searchable list, and the delete and clear actions (TAD-014, TAD-018) need commands. Search must answer in under 50 ms over 10 000 clips (SRC-01, non-functional requirement, MVP criterion 6). This ticket provides the IPC contract and its typed front wrappers.

## Scope

- Types in `src-tauri/src/clip.rs` (`#[derive(TS)]`, camelCase):
  - `ClipQuery { search?: string; cursor?: string; limit?: number }` — `limit` defaults to 50, capped at 200; the P1 fields of the spec (`kinds`, `app`, `tab`, `collectionId`) are added later as optional fields;
  - `ClipSummary { id, kind, preview, sourceBundle?, sourceName?, pinned, copyCount, lastCopiedAt }`;
  - `Page<T> { items: T[]; nextCursor: string | null; total: number }` — `total` = number of clips matching the query.
- `src-tauri/src/storage/fts.rs`: `match_query(input: &str) -> Option<String>` — splits on whitespace, strips FTS5 syntax characters, quotes each token and makes it a prefix term (`"sel"*`), joins with spaces (AND); empty → `None`. Diacritics are handled by the `remove_diacritics 2` tokenizer on both sides.
- `storage::clips::list(conn, &ClipQuery) -> Result<Page<ClipSummary>, StorageError>`: no search → `list_recent`; search → join `clips_fts` (`MATCH`) with the same newest-first order and cursor; invalid cursor → `AppError { code: "invalid_cursor" }`.
- Commands (async, database work off the main thread):
  - `list_clips(q: ClipQuery) -> Page<ClipSummary>`;
  - `delete_clips(ids: string[]) -> void` → `storage::clips::delete`, emits `clips://changed { removed }`;
  - `clear_history(keepPinned: boolean) -> number` → `storage::clips::clear`, emits `clips://changed {}` (reload);
  - `get_app_icon(bundleId: string) -> raw PNG bytes` (`tauri::ipc::Response`), `AppError { code: "not_found" }` when absent.
- `src/lib/api.ts` wrappers: `listClips(q)`, `deleteClips(ids)`, `clearHistory(keepPinned)`, `getAppIcon(bundleId): Promise<ArrayBuffer | null>`, `onClipsChanged(cb)`.
- Performance test seeding 10 000 clips.

## Out of scope

- Kind, app, tab and date filters (SRC-03…05), term highlighting (SRC-02), fuzzy fallback (SRC-06).
- `get_clip`, thumbnails, pin, snippets (phase 2); the UI (TAD-013).

## Acceptance criteria

- [x] Given clips "SELECT * FROM users", "vessel" and "Selected items", when `list_clips({ search: "sel" })` runs, then it returns the first and third only (prefix match per word), newest first, with `total = 2`.
- [x] Given a clip containing "Crème brûlée", when searching "creme brul", then it is returned.
- [x] Given a search containing `"`, `*`, `(`, `-` or `NEAR`, then no FTS5 syntax error occurs.
- [x] Given 120 clips, when `list_clips({ limit: 50 })` is paged with `nextCursor`, then pages hold 50, 50, 20 clips, `nextCursor` is `null` on the last one, `total = 120`.
- [x] Given `delete_clips([a, b])`, then both clips are gone and `clips://changed { removed: [a, b] }` is emitted.
- [x] Given `clear_history(true)` with 2 pinned clips among 10, then it returns 8, and `clips://changed` is emitted.
- [x] Given 10 000 seeded clips, when `list_clips({ search: "sel" })` runs 20 times, then the median is under 50 ms (test build).
- [x] Given a bundle id with a cached icon, then `getAppIcon` resolves to PNG bytes; without one, to `null`.

## IPC

- `list_clips(q: ClipQuery) -> Page<ClipSummary>` · `listClips(q)`
- `delete_clips(ids: string[]) -> void` · `deleteClips(ids)`
- `clear_history(keepPinned: boolean) -> number` · `clearHistory(keepPinned)`
- `get_app_icon(bundleId: string) -> bytes` · `getAppIcon(bundleId): Promise<ArrayBuffer | null>`
- Event `clips://changed` · `onClipsChanged(cb): Promise<UnlistenFn>`; an empty payload means "reload".

## Database

- No migration; uses `clips_fts`, `idx_clips_last_copied` and `app_icons` from TAD-009.

## Security

- The search string is never logged (log its length only); SQL uses parameters, the FTS query is built from quoted tokens.
- The seeded performance data is generated, not real clipboard content.

## Risks

- SQLCipher compiled at `-O0` in the test profile makes the 50 ms budget flaky → `[profile.dev.package.libsqlite3-sys] opt-level = 3` (or the crate name actually used) in `Cargo.toml`.
- Counting `total` on every keystroke → a single `count(*)` on the same filter; measured by the performance test.
- Prefix matching is per word, not substring ("vessel" does not match "sel") → accepted reading of SRC-01; noted in `PROGRESS.md`.
